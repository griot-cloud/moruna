# Changelog

## Unreleased

- **A lowered CPU limit is never exceeded by a task started after it.** A worker checked the bound before it picked and marked itself busy after, so a limit lowered in between let it start the task it had picked once the others had parked, and a worker still inside the bound could start one while a task from before the lowering ran: three workers busy under a limit of two for up to a task's length. The knob, the limit and the busy count now share one atomic word and a worker claims its busy slot against it with a compare-and-swap after the pick, so the busy count falls to a lowered bound as running tasks end and never climbs back over it (SDD 10 SC-I7 and f.2, amended 2026-09-30).
- **A peak reached before the machine shrank is judged against the ceiling it was reached under.** On macOS the report's peak is the kernel's lifetime mark, which the sampler reads rather than watches, so a peak from before a lowering could be read a few milliseconds after it and reported at 1.8 of a ceiling the run never ran under. The sampler now records the window the mark rose in (a record's peak has its `apply` as its window); when the ceiling moved or a drain began inside it, the peak is judged against the highest ceiling in force in that window, and the report's notes and its memory line say so, naming both ceilings (SDD 04 f.4, 03 f.2a).
- **A run on a machine that grows is not ended for having grown.** The controller took the limits each tick's sample carried, and a sample taken just before the machine grew carried the old ceiling: taken after the grown arena was reported, it left no room above the arena and a run could end with "footprint exceeds budget 0". A tick now keeps limits the watcher handed over after it sampled (SDD 11 f.15, RC-T19).
- **`moruna-vmm`: a refused vsock host stream ends cleanly on Linux.** A host that sent a bad `CONNECT` line to the monitor's Unix socket and more bytes after it (or whose connection the guest refused, or found no room) read `ECONNRESET` on Linux, where closing a Unix socket with unread bytes resets its peer; macOS gave end of stream. The monitor now shuts its side for writing and drains what the host still sends, up to 64 KiB and one second, before closing, so the host reads end of stream on every platform (MH 4.8.4, VM-T14).
- **`moruna-vmm`: the control socket's answer to an over-long request always arrives.** After answering a request line over 4096 bytes the monitor closed the connection at once, so a client still writing had its write refused, and on Linux one that had written past the line could read `ECONNRESET`. The monitor now shuts its side for writing and drains the client the same way (up to 64 KiB and one second) before closing: the client reads the error answer, then end of stream (VM-T18).
- **An explicit budget on Linux counts this process, not everything in its cgroup.** Where discovery found a cgroup it measured the cgroup's `memory.stat` whatever the budget was, so a run given an explicit budget in a container, or on a CI runner, was charged for every other process there: under `cargo test` it was charged for cargo's own 93 MiB and the test harness's parent, and 256 MiB runs were refused as below a floor of up to 360 MiB they had not made (`budget.host: ... The process held 272674816 bytes before the arena existed`). A Databricks driver's JVM would have been charged the same way. With an explicit budget, or a ceiling taken from the machine's RAM, the baseline, every sample and the report's peak are now the process's own anonymous memory (`RssAnon`, as macOS's `phys_footprint` is its own), and a note in the report says so; when the ceiling is the cgroup's limit the cgroup's figure stands, since the kernel enforces that limit on everything in it. File backed pages were never counted and still are not (SDD 03 DS-I4, DS-T15, DS-T16).
- **A safetensors file whose header was not padded reads correctly.** The reference writer pads the JSON header to eight bytes, so a tensor's data starts on an item boundary; a writer that does not pad can put a `float32` tensor at byte 91, and a `TensorSource` refused it (`byte offset 91 is not a multiple of the item size 4`). Such a range is now read from its own first byte, buffered, and the tensor is a view at offset zero. Found by the first end-to-end tensor job, which is now a test in the Python suite.
- **A shared cgroup's lifetime peak no longer sizes the run.** Where `memory.peak` cannot be reset (a cgroup the process may not write, as on a CI runner), it is the cgroup's peak since the cgroup was made, and a probe of a few hundred bytes was measured to cost everything the cgroup had ever held, so a run at any budget was refused as unsizeable. After a refused reset the sampler's own running peak is the peak.
- **A copy behind a slow sink no longer ends on a full arena.** A run with no kernel stage (a peQL plan into a contract write, say) read ahead of its sink until a read found the arena full, and the run ended with `alloc ... exceeds budget ... in use`: a queue over its high water that can evict is never counted full, nor is one waiting on an evicted head. It happened on a loaded machine, where the sink and a plan's re-reads are slow. The source drive now issues a read only when the arena has room for it beside the reads in flight, and issues no new read while an evicted entry waits to be read again, so the queue waits on the sink instead (SDD 10 f.5, SC-T22).
- **An unordered run resumes from any checkpoint it wrote.** A file sink fed out of order can commit a file holding sequence numbers on both sides of the point where everything below is committed (17, 18 and 20 in one file, 19 late in the next). The sink reported that point as its watermark, and a resume from it refused the checkpoint with "straddles the watermark", because keeping the file would have written row 20 twice; a SIGKILL resume test failed that way about one run in seventeen. The watermark now stops at the start of any committed file that straddles it, so a resume removes that file and replays its rows with the rest: every row still appears exactly once, at the cost of replaying up to about one more file. A checkpoint that genuinely disagrees with the store is still refused (SDD 08 f.7, SI-I8, SI-T17).

## 0.1.1

Fixes S1 for tight budgets. **Do not use 0.1.0**: its memory bound could be exceeded by about a percent at a tight ceiling, it was published from a failing pipeline, and it carried a Linux wheel only. It is no longer on PyPI.

- **The memory bound holds at a tight ceiling.** The controller planned morsels into the whole of the headroom the arena leaves above itself, and the morsels are not the only thing there: a Parquet writer's encoder, the Arrow builders a batch is converted through and the interpreter's own growth are all outside the arena, none of them in the model, and every one of them in the figure S1 is measured from. A Python kernel at a 512 MiB budget on a host with a large resting footprint reached 1.005 and 1.012 of its ceiling. The kernels are now planned into a share of that headroom and the rest is held back (11 f.3), and the same job peaks at 0.976 across resting footprints from 0 to 380 MB.
- **A kernel's fixed cost is funded before its first morsel.** One probe cannot tell a kernel that holds a fixed cost from one whose cost scales with the morsel, and the model read its whole measurement as the scaling term, which under-predicted a constant-cost kernel by the ratio of the morsel sizes. The probe now seeds both terms until a record separates them.
- **A budget that cannot hold a run says so before the run starts.** Where the smallest morsel the runtime can form does not fit the ceiling, `start` refuses with the arithmetic it refused on. It used to begin, run one morsel and report a footprint the process was already holding.
- **macOS wheels.** 0.1.0 published a Linux wheel only, because the publishing step cannot run on a macOS runner. Building and publishing are separate jobs now, so both platforms ship.
- **`inspect_host()['anon_bytes']`**: what the process is already holding, measured the way the runtime measures it. A budget is a ceiling for the whole process and the arena is sized from what was resident before it, so this is the figure a caller needs to choose one. Pages a memory pool is holding for reuse count too: on Linux pyarrow allocates through jemalloc, which does not return them until asked, so `pa.default_memory_pool().release_unused()` before a run can be the difference between a budget that fits and one that does not.
- The run report travels with the Python surface's budget diagnostics, so a ceiling passed on a host you cannot log into is answerable from the report alone.

## 0.1.0

Withdrawn. First release: Parquet to Python to Parquet inside a byte budget, spill to disk, resume from a manifest, Polars and DataFusion bridges. Its memory bound could be exceeded by about 1% at a tight ceiling (see 0.1.1), and the wheel was Linux only.
