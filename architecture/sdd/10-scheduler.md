**Decisions worth your eye:** (1) the source-drive loop and the sink-drive loop are two dedicated threads owned by the scheduler, not workers and not reactor threads, so read-ahead and writes never consume a worker slot and the only blocking waits on reactor completions in the process are theirs (contracts CT-I7); (2) the admission rule is evaluated per worker pick with an atomic stage cursor and one short lock, not by a central dispatcher thread; (3) errors terminate by default, `skip` records and continues, and a `budget(n)` policy terminates on the n-th failure; (4) every stateful instance exists before the first morsel is read (`init_instances`), so a failing `init` costs nothing and the baseline the controller samples already contains every loaded model.

## a. Purpose and boundary

The scheduler turns a linear chain of stages into work for a pool of role-free threads. It owns the workers, the stage table, the admission rule that decides which stage a free worker serves next, the stateful instance pools, the source-drive and sink-drive loops, completion detection, the error policy, the checkpoint thread, the worker heartbeat, and the emission of every trace record. It implements `Knobs`, `StatsSource` and `Prober` (contracts d.11) so the controller can move its parameters, read its counters and run the probe protocol without knowing its internals.

It refuses to know: where morsel bytes are (placement); how big a morsel should be (it reads the target from its knob and passes it to the source); why a worker count was chosen (controller); what a kernel does.

## b. Vocabulary

**Task.** One unit a worker executes: `Apply { stage, morsel }`. Source reads and sink writes are not tasks; they are driven by the two drive threads.

**Stage table.** Per kernel stage: the kernel, its instance pool, its input queue id (stage−1) and output queue id (stage), and its stats.

**Active set.** Workers permitted to take tasks; the rest are parked (`workers.active ≤ workers.max`).

**Admissible stage.** A stage with a resident head in its input queue and whose output queue is not full.

**Instance pool.** For a stateful kernel, exactly `max_instances` `KernelState`s, all created by `init_instances` before the run starts, with worker affinity. A stateless stage has no pool and no instances.

**Source drive.** The thread that issues `Source::read` calls up to `read_ahead` in flight, waits on their completions, and pushes results to Q0.

**Sink drive.** The thread that pops from the last queue and calls `Sink::write` up to `sink.concurrency` in flight.

**Drive-side helper.** A request the source drive services on behalf of another thread (the probe's stage-1 read, f.9), so that the requesting thread never waits on a reactor completion itself.

**Heartbeat.** A per-worker timestamp each worker refreshes at every loop head and after every `apply`; a worker that is neither running `apply` nor refreshing for `heartbeat_interval_ms` is dead (f.14).

**Completion.** The condition: source exhausted, every queue closed and empty, no task in flight, no sink write in flight.

## c. Invariants

**SC-I1. Workers run only `apply`.** A worker thread never calls the reactor, never waits on a `Completion`, never allocates payload memory; it pops, applies, pushes, records. Upholds preamble 4.1 and G-I9.

**SC-I2. What runs next is the policy's (KD7b, restated).** Each free worker's next unit is chosen by the run's scheduling policy (contracts d.18), named by the `scheduler.policy` setting and made from a registry, from the units ready for that worker. The `admission` policy is this invariant's earlier rule: among ready units, the stage whose output queues hold the fewest bytes first, ties toward the later stage (closer to the sinks), then the port whose queue holds the most bytes. Swapping the policy is a setting, never a code change; an unknown name is refused at `new` naming the registered ones.

**SC-I3. Source work is admitted only when Q0 is below high water and read-ahead has room.** The source drive issues a read iff `!placement.is_full(0)` and `in_flight_reads < read_ahead`. And the arena has room for it: a fresh read is issued only when the arena's free bytes for the host tier (`alloc.available(tier0)`) cover what it and every read already in flight may be charged, and only while Q0 holds no evicted entry awaiting its re-read (f.5, amended 2026-09-29). The sum of what Q0, the reads in flight and the sink's writes hold is thereby bounded by the arena itself, whatever Q0's high water is.

**SC-I4. Every morsel yields exactly one trace record per stage.** Emitted by the worker after `apply` returns or fails, and by the probing worker for the probe record (f.9, `probe.rs`); never twice, never skipped. Upholds G-I4.

**SC-I5. Knobs have one writer and take effect within one pick.** `Knobs::set` stores atomically; the next worker pick and the next drive iteration observe the new value. Upholds G-I5.

**SC-I6. A stateful instance is used by one worker at a time and affinity is preferred.** An instance is acquired under the pool lock; a worker re-acquires the instance it last used when free; every instance is created by `init_instances` before the run and the pool is full from the start (f.4).

**SC-I7. Parking is lossless.** Lowering `active_workers` parks workers only between tasks; a parked worker holds no morsel and no instance. (Amended 2026-09-30.) The workers that take tasks are `min(workers.active, cpu_limit)` at every instant after a lowering is stored, counted: a task already running when the bound falls finishes and holds its busy slot until it ends, so the busy count falls to the new bound and never rises above it again, and no worker starts a task while it is outside the bound or the bound's slots are all held (f.2's claim).

**SC-I8. Errors follow the policy and never panic the pool.** A kernel error or panic is caught on the worker; under `Terminate`, the run enters termination with the diagnostic; under `Skip`, a trace record with `Outcome::Error` is written, the morsel is dropped (and the sink told to skip its seq); under `Budget(n)`, errors 1 to n−1 are skipped and the n-th terminates. Upholds G-I8.

**SC-I9. Completion is exact.** `run` and `run_resumed` return only when the completion condition holds or the run terminated or was cancelled; no morsel is left in any queue on normal completion; every run that entered `Running` returns `Ok(RunOutcome)`.

**SC-I10. Knobs are clamped here and forwarded once.** A knob value outside the preamble's range is clamped to the nearest bound and counted in `SchedulerStats::knob_clamps`; `StagingTrigger`, `HighWater` and `PromotionWindow` are forwarded to the placement engine by the scheduler and by nobody else (contracts d.11).

**SC-I11. A dead worker is noticed within two heartbeat intervals.** The heartbeat table is checked at least once per `heartbeat_interval_ms` for the whole run; a worker found dead terminates the run with an internal diagnostic naming the worker and its last task, never a hang. Upholds G-I8.

**SC-I12. Nothing runs or is pushed past the catalog's budget (KD7b, adaptive-runtime 9.4 step 1, 12.5).** A unit runs only once the bytes it is predicted to make (less its input's, when its take is the input batch's last) are claimed from the placement's catalog (`Residency::reserve`, contracts d.17); a unit whose claim is not granted is never run, whatever the policy's preference. Every push the scheduler makes, a unit's output, a source's read, a re-read for `replace`, is admitted under a claim: an output larger than its prediction tops its claim up; a top-up that is pending waits for the room on its way; one refused because nothing can leave memory sends the batch straight to disk (`push_spilled`); with no disk tier the push waits for consumers to make room and, after `PUSH_STALL` by the run's clock with none, the run ends with a `Staging` diagnostic naming the morsel and the bytes. No push is made with the contract's unclaimed `push`. A budget under the run's floor (placement f.18 rule 13: every queue's promotion window and one unit's input and output at `morsel.min_bytes`) is refused at `new` with `Config(budget.host)` naming the floor and its terms, before anything is opened or read. A run never hangs quietly: the stall detector (f.21) ends one that nothing can move.

**SC-I13. A decision keeps to its budget (KD7b, 9.4 step 4).** Every decision is timed against a budget, one percent of the median of the last 64 units' durations and never below `DECISION_BUDGET_FLOOR_NS`; a decision over it hands the next decision to the `admission` baseline, and `SchedulerStats::policy` counts both. The run reports decisions, decision time, decisions over budget, fallbacks, units admitted and units whose claim was not granted, worker time idle while a unit was ready, and the budget's unused bytes times the time they stayed unused while a unit was ready.

**SC-I14. Predictions come through the model's port, with a spread, or are marked as ratios (KD7c, adaptive-runtime 9.3, 9.4).** With a cost model set (`Scheduler::set_cost`), every ready unit and every stage's typical unit is predicted by the deciding model through `CostModel::predict` (via `moruna_cost::Online`), its bytes out and wall time at the median and the 95th percentile, marked `PredictedBy::Model` and `drifting` when its key drifts; with none, by the stage's measured ratio of bytes out to bytes in and its mean unit time, each a point, marked `PredictedBy::MeasuredRatio`. A unit's claim is its prediction's 95th percentile held to the budget above the run's floor plus one batch (f.22), so a prediction too large by any factor never leaves a unit waiting for room that can never come, and one too small is topped up or goes to disk (f.20). `SchedulerStats::policy` counts the units run on each.

**SC-I15. Learning never waits on the store (KD7c, adaptive-runtime 9.6).** Every unit a worker finishes that produced is settled into the run's models in memory, before its record is emitted: the deciding model and the shadow learn it online and its drift is judged. No worker writes to the store: the run's thread (the one `run` blocks) appends what was kept at least every 10 ms or 256 units, and at the run's end, after the workers are joined, writes the rest and the fitted state. A store that refuses is counted in the report with its reason, and the run goes on.

**SC-I16. A policy keeps to its budget by going shallower (KD7c, 9.4 step 4).** `lookahead` times each simulation and starts none that would end past the decision's budget; a decision it cut short answers with the best it found, or `residency_greedy`'s order, and counts `shallower`; a simulation the simulator refuses is counted with its reason and answered by the greedy order. A drifting key makes it one step deep.

**SC-I17. A stage's `finish` runs when its input ends, and what it gives goes downstream (0.6.1, contracts d.7).** For a stateful stage, the close cascade (f.7) does not close its outputs when its inputs are sealed and drained and no task runs: it hands the stage to a worker (`WorkerJob::Finish`), which calls `Kernel::finish` on every live instance in instance order. Each batch one gives is a morsel of the stage, numbered from the stage's finish base (contracts d.16: one past the highest number its input carries, then one more for each batch), pushed into every output queue under a claim like an `apply`'s output, counted in the stage's counters and leaving one trace record; then the stage's finish count is set and its outputs close, so the stages and sinks after it take those batches before their own inputs end. The first `Err` (a panic is one) ends the run as `Terminated` naming the stage and the number the batch would have had; the outputs close either way. A stateless stage has no `finish` to call and gives nothing at its end.

**SC-I18. A stage that joins its inputs by morsel applies one set of one number (0.6.1, contracts d.16).** For a kernel whose `aligns_inputs` is true (`moruna.std.join`), a worker that takes a morsel on one port keeps it with the others of its number until every port has given one, and only then calls `Kernel::apply_aligned` with the set, port 0 first; the output keeps the number, the record is one per set, and each port's share is released once the call returns. A set its ended inputs will never complete ends the run naming the stage, the number and the ports it came on, unless the error policy skipped a morsel upstream, in which case the incomplete sets are dropped and counted as the stage's skips.

## e. Data model, formats and state machines

### e.1 Worker state machine

`Parked` → (unpark, active slot available) → `Idle` → (pick) → `Running(stage, seq)` → `Idle` → (active lowered) → `Parked`. Cancellation moves `Idle` and `Parked` workers to `Exited` and lets `Running` finish first. `init_instances` and the probe (f.9) run on a worker in `Idle` with the others `Parked`.

### e.2 Run state machine

`Init` (after `new`) → (`init_instances`; the controller's probes through `Prober`; on a resumed run also `apply_resume_point`) → `Running` (entered by `run` or `run_resumed`, which start the drives and the checkpoint thread) → `Draining` (source exhausted, closing queues in order as each empties) → `Finishing` (sink `finish`) → `Completed`; from `Running` or `Draining`, `Terminating` (error under policy, or `Knobs::terminate`) → `Terminated`; `Cancelling` → `Cancelled`. The checkpoint thread runs while the state is `Running` or `Draining` and is stopped on leaving them. In `Terminating` and `Cancelling`: source drive stops issuing; workers finish current tasks; placement `shutdown`; in-flight sink writes complete; the final manifest is written by the scheduler when checkpointing is on (f.12); trace `flush` (the facade calls `finish` once, 04 TR-I5).

## f. Algorithms and policies

**f.1 Startup (`new`).** In the facade's startup order (12 PY-I1) the scheduler is built after placement and before the controller. `new`: validate the chain, `PayloadSpec::check` of each kernel against the upstream schema (contracts CT-I5) and the sink's `accepts` against the last kernel's `output_schema` (or the source schema when there are no kernels); call `source.plan()` once and keep the splits (the facade's own `plan` call, 12 f.1, is the same call and must return the same list; a source caches it); `set_consumer` on every queue; detect resumability: `sink.checkpoint()? == None` means a non-resumable sink (contracts d.8, the detection rule stated there), so `checkpoint_enabled` is forced false with `sched.not_resumable` naming the sink, and `source.repeatable() == false` forces it false too, naming the source; when `!cfg.resuming`, `sink.open(schema)`; spawn `workers_max` threads parked; spawn the two drive threads idle (the source drive answers only helper requests, f.9, and issues no read of its own; the sink drive pops nothing) until `run` or `run_resumed` starts them driving. The checkpoint thread is not started; the sink is not opened when `cfg.resuming` (`apply_resume_point` resumes it, so a resumed run never opens it twice). Then the facade calls `init_instances` (f.4), the controller's `prepare`, `probe_all` (which calls `Prober::probe`, f.9), `start`, and finally `run`.

**f.2 Worker loop.**

```
loop:
  heartbeat[w] = now()
  if !active_slot(): park(); continue
  (stage, port, claim) = decide()                    // f.3: the policy's first unit whose claim is granted; none → park 1 ms, continue
  claim_busy_slot()                                  // SC-I7; refused → park 1 ms, continue
  (state, slot) = acquire_instance(stage)            // f.4; NoState for a stateless stage; None → re-pick, nothing taken
  (morsel, wait_us) = placement.pop_blocking(stage-1, spec[stage], Locality::Any)   // resident by construction of pick, so wait_us is normally 0; None (closed) → release_instance, continue
  t0, c0, s0 = now(), thread_cpu(), sampler.sample()
  result = catch_unwind(|| kernel.apply(state, morsel.payload))
  t1, c1, s1 = now(), thread_cpu(), sampler.sample()
  placement.release(stage-1, morsel.seq)             // KD7a: the unit is done with its input; before the push, so its bytes go first
  heartbeat[w] = now()
  state_bytes = state.footprint().unwrap_or(0)       // while the instance is still held
  release_instance(slot)
  match result:
    Ok(out)  → out_morsel = morsel.with_output(out); admit_push(outputs, out_morsel, claim); record(Ok)   // f.20
    Err(e)   → apply_policy(e); record(Error)
  loop
```

**The claim (amended 2026-09-30).** `active_slot()` at the loop head reads the bound before the pick, so on its own it cannot keep a lowering: a limit lowered between the check and the task let a worker outside the new bound start the task it had picked after the others had parked, and a worker inside it start one while a task from before the lowering still ran, three busy under a limit of two for up to a task's length (`cpu_limit_bounds_active`, once, on a loaded macOS gate). The knob, the CPU limit and the busy count therefore share one atomic word, and after the pick the worker claims a busy slot with a compare-and-swap that succeeds only while its index and the busy count are both below `min(workers.active, cpu_limit)` in that word; `Knobs::set(ActiveWorkers)` and `set_cpu_limit` write the same word, so every claim after a lowering sees it. A refused claim holds nothing (the pop has not happened) and the worker parks for a millisecond and goes round the loop; the slot is released when the task's counters are down, on every path out of the task. `SchedulerStats::workers_busy` is the busy count of that word. The probe's worker (f.9) claims its slot unconditionally, because it runs alone once every other task has ended.

`record` builds the `TraceRecord` (contracts d.13) from `morsel` (features, bytes_in), `out` (bytes_out, rows_out, tier_out), timings, the knob snapshot, `placement_miss_wait_us = wait_us` (the second element `pop_blocking` returned, PL-I9), `state_bytes`, `instance` (the slot index, `u16::MAX` for a stateless stage), `cpu_time_us = c1 − c0`, and the memory fields with these semantics (shared with RC f.4): `mem_anon_before = s0.anon_bytes`, `mem_anon_peak = max(s0.anon_bytes, s1.anon_bytes)`, `throttled_delta_us = s1.throttled_us − s0.throttled_us`, `dev_mem_peak = s1.device_used[d]` for the instance's device (0 otherwise). The sampler's monotonic `peak_anon_bytes` is not used per record; it belongs to the probe (f.9). After `trace.record(r)` the worker calls the installed `RecordHook`, if any, with `&r` (the controller's `on_record`, RC d.1); the hook is cheap by contract and runs on the worker.

**f.3 Deciding (restated by KD7b; was `pick`).** A free worker gathers the units ready for it: for each stage it may serve (`instances::admissible`) none of whose output queues `is_full`, each input port whose head is resident for the stage's spec (`peek_resident`), with the head's batch (`Residency::head`: its id, number, bytes, whether this take is its last, when it arrived), the input queue's bytes and the output queues' (from `placement.stats()` cached for a millisecond), the unit's prediction (SC-I14, f.22), its critical-path weight (the predicted work queued on the longest path from its stage to a sink: its stage's backlog times a unit's median over the units it may run at once, plus the heaviest such weight downstream) and how long its head has been ready for it (since the first decision that saw that head ready there). With them go the machine (the active workers, the host tier's budget and what is resident or claimed, the declared disk bandwidth, the claim cap) and every stage's snapshot (each port's batches and bytes in memory and on disk, the units under way by how long each has run from the heartbeat table, how many may run at once, and a unit's prediction: a ready head's of the stage when it has one, else at its mean input so far). It hands them, the DAG and the catalog's port to the run's policy (`SchedulingPolicy::decide`, contracts d.18), timed against SC-I13's budget, and tries the actions in order: `Run` claims the unit's prediction's 95th percentile held to the claim cap, less the head's bytes when the take is its last (SC-I12), and runs the first whose claim is granted; `Spill` and `Reload` go to the catalog, and a refusal ends the run (the policy asked for what the catalog's rules forbid); `Wait` stops. When a unit was ready and none ran, the worker's park counts as idle while ready. The policy is one object for the run, decided under the scheduler's decision lock; the claims are made after it is released. `pick.rs` is gone: its rule is the `admission` adapter (`policies/mod.rs`); `fifo`, `residency_greedy` (f.23) and `lookahead` (f.24) are the others this build ships.

**f.4 Instances (amended 2026-11-07).** `init_instances`: for each stateful stage in order and each instance `i` in `0..max_instances`, the worker `(b + i) mod workers_max`, where `b` is the number of instances of the stateful stages before it (unparked for the call, the others parked), runs `kernel.init(InitCtx { instance: i, device: assigned round-robin over devices when `uses_device_memory`, alloc })` and stores the slot with `owner = Some(that worker)`; the first `Err` stops the loop and is returned as is (a `Kernel` error from `init`, adapters AD-I7), with nothing read or written (architecture 7, "stateful init fails"; SC-T18). The run's instances are dealt to the workers in turn across its stages, and a restored or re-created instance keeps the worker this rule gives it. Before this, `i` alone named the worker, so every stage with one instance (every `moruna.Function` subclass) lived on worker 0 and stateful stages on separate branches ran one after another (0.6.3: six branches of 0.5 s took 3.7 s). Stateless stages get no instances. `acquire_instance(stage)`: lock pool; prefer a free slot whose `owner == this worker`; else any free slot; else return `None` and the worker re-picks (the stage was admissible only if a slot was free, so this is a race, not a policy). The instance is acquired before the pop (KD7a, 2026-10-29): a batch a worker takes is held in placement's buffer catalog until it is released (09 f.18, PL-I19), so a lost race must be settled before anything is taken; the earlier order popped first and pushed the morsel back to the tail of its queue, which put a taken share back as a second batch and moved it behind every later one. A slot is retired after a kernel error or panic (adapters AD-I7 rationale) and re-created by `kernel.init` on the next acquire by the worker that acquires it; that is the only `init` after `init_instances`. On a resumed run, `apply_resume_point` fills the pools (f.13) and `init_instances` is not called by the facade.

**f.5 Source drive.** A thread, idle until `run` (f.1). Iterate the splits kept by `new`; for each, while `in_flight < read_ahead` and `!placement.is_full(0)` and not stalled by an ordered sink (`sink.is_stalled()`, `Ordered` handles only): compute the row range from the morsel target (`morsel_target[1]`, the first kernel's target, or `morsel_target[0]` when there is no kernel, h) and the split's bytes per row (`uncompressed_bytes / rows`), clamp the byte size to `[morsel_min, morsel_max]`, sub-split when `sub_splittable`, and never below one row: when one row's estimated bytes exceed `morsel_max` the range is exactly one row and the morsel passes at its natural size (architecture 7, "a single row larger than the maximum morsel"; the trace shows it through `bytes_in`, and the controller sizes around it, RC h); issue `source.read(split, range, alloc, tier0)` where `tier0` is `PinnedHost` if `alloc.is_pinned()` else `Host`; on completion (the drive polls the returned future and `wait`s on the completions inside it; this thread is one of the two the contract permits, CT-I7), `placement.push(0, Morsel::new(seq++, 0, payload, origin))` with `origin.node = cfg.node`. The drive keeps its position as a `SourceCursor { split_index, row_offset, next_seq }` (the next range to issue, not the last completed one) and exposes it for f.12; sequence numbers are assigned at issue in cursor order, so the cursor and the sequence counter always agree. Also service `placement.evicted(0)` by re-issuing reads for evicted entries and calling `replace(0, morsel)`, and service drive-side helper requests (f.9). A read that fails with `Alloc` (a single row larger than the budget) or `Source` terminates the run naming the split and the row range (h). When the plan is exhausted and no read is in flight, `placement.close(0)` and set `source_exhausted`. With `read_ahead = 0` the drive issues one read at a time only when Q0 is empty (a floor of one).

**f.5 Splits with no rows (amended 2026-10-28, MA1).** A split may hold no rows: a query whose result is empty is a plan of one such split, and a partition with no rows is one among others. The cursor steps past every split it has no rows left in, a split it has read to the end and a split that holds none alike, whenever it is read or advanced (the next range to issue, the look at it that admission takes, and the exhaustion check), all under the cursor's lock. So the plan is exhausted exactly when no split at or after the cursor has a row left, and "the cursor is past the last split" means the same thing. No read is ever issued for a split with no rows. Before this, only taking a range stepped the cursor past such a split; the look admission takes stepped past it on a copy, so when every split left held no rows no range was taken, the cursor stayed on the empty split, Q0 never closed and the run never finished (`SELECT 42 AS answer WHERE false` through a `datafusion` source waited until it was cancelled). A split with no rows between two that hold rows was stepped past by the next take and never stalled; one at the end of the plan, or a plan of nothing else, did.

**f.5 Arena admission (amended 2026-09-29).** `!placement.is_full(0)` does not keep the drive's reads inside the arena, for two reasons found together on a peQL copy at 256 MiB behind a slow sink (H6, `fix/copy-admission`). A queue over its high water with a candidate to demote or evict is not full, it is draining (09 f.14), so fresh reads go on past the mark while the planner takes entries off the tail; and a queue whose head is evicted is planned no further until the head is replaced (09 f.2 step 1), so it is neither full nor draining, whatever it holds. (A run with no kernel gets no `HighWater` knob, RC f.3, so its Q0's mark is 09 f.8's default, the placement half of the arena the controller sets at `prepare`: 46.4 MB of that run's 92.8 MB arena.) On that run Q0 passed its mark, the planner evicted its seven youngest entries, the drive re-read the two nearest the head, and a plan source's re-read runs its partition again from the start, which on a loaded machine took longer than the twenty fresh reads issued after them; the sink drained to the evicted head and stopped, the fresh reads filled the arena (Q0 27 entries, 83.8 MB of a 92.8 MB arena, four reads in flight, no write in flight), and the next read's `Alloc` ended the run (h). Two rules close it, both on fresh reads only. First, a fresh read is issued only when `alloc.available(tier0)` is at least its charge plus the charges of every read in flight, fresh or replacement; a read's charge is its range's share of the split's `uncompressed_bytes`, scaled by the largest ratio of a completed read's `payload.bytes()` to its own estimate seen so far in the run (never below 1, since `Split::estimated` estimates may be low) and doubled, because the arena charges each buffer the power-of-two class it rounds up to (02 AR-I2, e.2). An allocator with no budget for the tier (`available` is `None`) bounds nothing. When the arena has no room and nothing the run holds is on its way to being released (no read in flight, no write in flight, no worker busy, every queue empty), the read is issued anyway and the arena decides, so a row larger than the budget still ends the run naming its split and rows (SC-T17) rather than the drive waiting for bytes nobody will free. Second, no fresh read is issued while `placement.evicted(0)` is not empty: an evicted entry exists because Q0 was over its high water, its re-read needs back the room its eviction gave, a fresh read lands at the tail where the planner evicts next, and when the evicted entry is the head nothing leaves Q0 until it is back. Replacements are not gated (they are what the queue is waiting for) and stay bounded by the read-ahead window; their charges count against fresh admission. Q0 of a copy therefore fills the arena less the reads in flight and waits on the sink, which is backpressure rather than a refusal (SC-T22).

**f.6 Sink drive.** A thread, idle until `run` (f.1). Loop: pop the head of Qn (`n` = number of kernels; Q0 when there are none) with `pop_blocking(n, sink_spec, Locality::Any)` when checkpointing is on, or with `pop` followed by a park bounded by `heartbeat_interval_ms` (unparked by any push to Qn) when it is off, so that the heartbeat check (f.14) runs at least once per interval in either configuration; on `Some(m)`: `sink.write(m.seq, m.payload)` (the reorder buffer, when present, is the sink and orders internally); keep up to `sink_concurrency` writes in flight, waiting on their completions; when a write resolves the sink no longer holds the batch and the drive calls `placement.release(n, m.seq)` (KD7a, 09 f.18; a morsel a resumed sink drops below its floor is released at once), and a release that fails ends the run like a failed write; after each write completes, read `sink.committed_seq()` and, when it moved, call `placement.set_committed(w)` (f.11). The sink is not a stage and emits no trace record; its throughput is visible through the last queue's drain rate and `SinkStats`. On `None` (closed and empty) with no write in flight: claim the exit, `finish` the sink, signal completion. Every stateful stage's `Kernel::finish` has run by then (SC-I17, amended 2026-11-04): it runs when the stage's own input ends, on a worker, and the sink's queue closes only after every stage upstream of it has finished, so what a `finish` gives reaches the sink before the sink commits anything. A `finish` that fails ends the run before any sink is finished (as on a cancel, f.10).

**f.7 Draining and closing.** When the source is exhausted and Q0 is empty and no stage-1 task is running, `close(1)`; and so on down the chain; each queue is closed when its producer stage has no task running and its input is closed and empty. This is evaluated by whichever worker or drive observes the condition (a monotonic check, safe to evaluate concurrently), one queue per pass and with the three reads in this order: **the input queue is already closed in the engine, then its count, then the stage's `running` counter.** The order is what makes the condition mean anything. Nothing can be pushed into a closed queue, so once the input is closed its count is final; a worker takes its claim on the stage before it pops (f.2), so reading `running` after the count catches a morsel in flight in one read or the other. A count read before the input was closed, or a cascade that closes several queues against one snapshot of the counts, closes a queue under a morsel that arrived in between: the sink then finds its own queue closed and empty and the run completes without that morsel, which is SC-I9 broken at about one run in a hundred of a three-stage chain (found by SC-T8 and SC-F5, 2026-09-23). The scheduler's own "closed" flag for a queue is therefore published only after `Placement::close` has returned, and the right to close a queue is claimed separately so the close still happens once.

**f.8 Error policy.** `apply_policy(e)`: `Terminate` → set run state `Terminating` with `e` as the diagnostic (enriched with the morsel's seq, stage, features and the `s1` sample); `Skip` → drop the morsel and call `sink.skip(seq)` (the contract's method; a `ReorderBuffer` advances past the sequence and forwards it, a file sink counts it as committed for its watermark, SI f.7), so a skipped morsel never holds the commit watermark back; on resume a skipped sequence above the watermark is replayed like any other and may be skipped again; `Budget(n)` → errors 1 to n−1 are `Skip`, the n-th (when `errors_total == n`) is `Terminate`; `Budget(1)` therefore equals `Terminate`. A kernel panic is converted to `MorunaError::Kernel { msg: "panic: ..." }` first. `MorunaError::Refused` (a request the allocator guard refused inside `apply`, 05 f.12; E13, 2026-10-02) is enriched like `Kernel` (the morsel's stage, seq and features replace the adapter's sentinels) and then follows the policy like any kernel error (05 f.13). One exception precedes the policy: an `Alloc { tier: Device(_) }` error from `apply` (device out of memory, architecture 7) is built into a `TraceRecord` (`Outcome::Error`) that is passed to the record hook only, not to `TraceSink::record` (so SC-I4 and TR-I2 hold: the trace sees one record per stage and morsel), the controller's f.11 shrinks the stage's device footprint inside that hook, and the morsel is then retried once on the same instance; the retry's outcome is the record the trace receives, and only a second failure of that morsel reaches `apply_policy`. `Knobs::terminate(diagnostic)` (contracts d.11) takes the `Terminate` path with the controller's diagnostic, from the controller's thread, regardless of the policy.

**f.9 Probe protocol (`Prober::probe(stage, bytes)`).** Park every worker but one (the probing worker). Obtain the input: for `stage == 1`, send the source drive a helper request for one read of about `bytes` (rows = `bytes / bytes per row` of the current split, clamped to the split and to one row at least) at the cursor, advancing it; the drive issues and waits on the read and pushes the morsel to Q0 with the next `seq`, then acknowledges; for `stage > 1` the input is the head of Q(stage−1), the previous stage's probe output. The drive answers helper requests in `Init` too, before `run`, which is when the controller probes. Then on the probing worker: `sampler.reset_peak()`; `s0 = sampler.sample()`; pop with `pop_blocking(stage−1, spec[stage], Locality::Any)`; run f.2's body once for `stage`, capturing `s1 = sampler.sample()` after `apply`; push the output downstream as normal (nothing is wasted; with the sink already open, f.1, a last-stage probe output simply waits in Qn until the sink drive starts in `run`); write the trace record with `Outcome::Probe` from the probing worker (SC-I4); return `ProbeResult { bytes_in, rows_in, peak_delta = s1.peak_anon_bytes − s0.anon_bytes (saturating), dev_peak_delta = s1.device_used[d] − s0.device_used[d] (saturating, 0 without a device), wall_ns, cpu_ns }`; unpark. All other workers are parked for the whole call, so the peak the sampler reports is the probe's own. A probe of a stage with no kernel (`kernels=[]`) is a `Plan` error; the controller does not ask (RC f.3). **How the others are held off (amended 2026-09-30).** The probe raises the gate and then waits for the busy count to reach zero. The gate stopped `pick`, but a worker that had passed `pick`'s gate check before the gate went up could claim its slot after the probe saw zero and run its task beside the probe's, so the peak and the wall time the probe reported could include another morsel's (found with f.2's claim, SC-I7). The gate is therefore a bit of the same atomic word as the busy count, and f.2's claim is refused while it is up: a worker that picked before the gate went up either claimed before it did and is counted in the zero the probe waits for, or claims after and is refused, holding nothing, and parks. The probing worker's own claim ignores the gate. `init_instances` and a restore raise the same gate (f.4, f.13).

**f.10 Cancellation and shutdown.** `cancel` observed by drives and workers between tasks; state `Cancelling`; f.7 is skipped; placement `shutdown`; sink writes in flight complete; the final manifest is written by the scheduler (f.12) when checkpointing is on; sink `finish` is not called; the checkpoint thread is stopped; trace `flush`; return `Cancelled { manifest }`. `shutdown()` (d.1): set the cancel flag, unpark every worker and join all of them (a `Running` worker finishes its `apply` first, bounded by the longest kernel), stop the drive threads (the source drive lets in-flight reads resolve and drops the buffers; the sink drive lets in-flight writes complete) and join them, stop and join the checkpoint thread; idempotent; called from `Drop`, so dropping a scheduler that is not running costs a few joins.

**f.11 Commit watermark.** The sink drive owns the watermark `w`: after each completed write and after each `sink.skip`, `w' = sink.committed_seq()` (the sink already counts skipped sequences, SI f.7); when `w' > w`, `placement.set_committed(w')` and `stats.committed_seq = w'`. Two threads reach that point, the sink drive after a write and a worker after a `skip` under a skipping error policy (f.8), so the right to make the call is claimed and held for the length of it: placement f.11 ignores a value below the watermark with a `debug_assert`, and a thread that reads `w'` and then calls with the claim already released can be overtaken and make the later call with the smaller value. The claim is the scheduler's own state and no lock is held across the call into placement (preamble 4.2); whatever arrived while the call was running is published by the same thread on its way out. With a sink whose `committed_seq` is always `None` (not resumable, detected at `new`, f.1), `w` never moves, the lineage index grows for the run, and `checkpoint_enabled` is false; the run is correct, only not resumable. At `Finishing`, after `sink.finish()`, `set_committed(next_seq − 1)`.

**f.12 Checkpoint thread.** When `checkpoint_enabled`: a dedicated thread (preamble 4.1; not a reactor thread, because `KernelState::checkpoint` may run kernel code, and not a worker), started by `run` or `run_resumed` on entering `Running` and stopped on leaving `Running`/`Draining`; it wakes every `checkpoint_interval_ms`, checks the heartbeat table (f.14), and calls the internal `checkpoint_now`. `checkpoint_now`: gather `CheckpointExtras { kernel_states, sink_state, committed_seq: w, source_cursor }` where `kernel_states` comes from calling `KernelState::checkpoint` on every instance of every `ResumePolicy::Checkpoint` stage (each instance is acquired for the call like a task, so no `apply` runs concurrently on it; SC-I6), `sink_state` from `sink.checkpoint()`, and the cursor from the source drive; then `placement.checkpoint(&extras)`, which writes the manifest with `std::fs` on the calling thread (placement f.12: temp file, fsync, rename; not through the reactor). A `Checkpoint` kernel whose `checkpoint` returns `Ok(None)` is a kernel bug: the run terminates with `Resume` naming the stage. Failures are counted and logged; three consecutive terminate the run (placement h). The thread never holds the stage table lock across the placement call. On termination and cancellation the scheduler itself calls `checkpoint_now` once more, from the thread that drives the exit, before stopping the checkpoint thread, and on **completion** as well when `checkpoint_keep` is set: a completed run whose wall time was shorter than `checkpoint.interval_ms` had no tick, so without this `checkpoint.keep` kept an empty directory and 12 f.7's promise that the report names a manifest was false (PM, 2026-09-22, on the first end-to-end run). Without `checkpoint_keep` a completed run writes no final manifest, because the facade is about to remove the directory. The facade never writes a manifest itself. A manifest asked for on demand (`request_checkpoint`, and `checkpoint_now`, which waits for it; MH 4.3 `checkpoint`) is written on this thread too, at once rather than at the end of the interval; `checkpoint_now` refuses at once, before counting the request, when the run is not `Running` or `Draining`, because only a live run has this thread, and a request counted before `run` and refused to its caller by timeout used to be served when the thread started, writing a manifest nobody was waiting for (SC-T21). Amended 2026-11-04 (SC-I17): `checkpoint_now` takes the manifest lock a stage's finish holds, and once a `finish` has given a batch it writes nothing: the thread skips its ticks, an on-demand request is refused naming why, and the final manifest is not written, so the run's last manifest is the one before the batches made at a stage's end.

**f.13 Resume.** Two steps, both on the facade's runtime thread. `apply_resume_point(point)`, in `Init`, in this order: refuse with `Resume` if `!checkpoint_enabled` before touching the sink (a resumed run must be able to write its own manifests); the message names the sink when the reason is a non-resumable sink (the f.1 detection) and the staging directory otherwise; `sink.resume(schema, sink_state, committed_seq)` instead of `open`, with `sink_state` the checkpointed bytes or an empty slice when `extras.sink_state` is `None` (a sink returning `Resume` ends the attempt with that error naming the sink; nothing has been written); set the source drive's cursor and sequence counter from `point.extras.source_cursor`; set `w = committed_seq`; for each `Checkpoint` stage, build instances from `kernel_states` through `kernel.restore(InitCtx, bytes)` in instance order on the owning worker; for each `Reinit` stage run the `init_instances` loop of f.4 for that stage (`Forbid` was refused by `Placement::restore`); keep `point.to_recompute`. The facade then runs the controller's `probe_missing` (RC f.14) and `start`, then calls `run_resumed(cancel)`: before the source drive issues new reads, it re-reads every `(seq, origin)` in `to_recompute` in order through the normal source path (`source.read(split_of(origin), Some(origin.row_start..origin.row_end), alloc, tier0)`) and pushes each to Q0 with its original `seq` (`Morsel::new(seq, 0, payload, origin)`), counting `stats.recomputed`; the re-reads obey `read_ahead` and `is_full(0)` like any other read, so a large recompute list does not blow the budget; then it continues exactly as `run` from `Running` (drives, checkpoint thread, `stats.resumed = true`). Sequence numbers above the cursor's `next_seq` are never reused, and the ones below it that are not in the lineage are, by construction, committed or skipped. Output equals an uninterrupted run (PL-T17).

**f.14 Worker heartbeat.** `heartbeat[w]` is an `AtomicU64` of nanoseconds, written at the points marked in f.2, plus `task[w]: (stage, seq, t_start)` while in `Running`. A checker runs at least once per `heartbeat_interval_ms` (1 s): on the checkpoint thread at every wake when checkpointing is on, otherwise on the sink drive at every wake of its bounded park (f.6). A worker is dead when it is not parked, its thread handle reports finished (`JoinHandle::is_finished`), and it did not exit through cancellation; a worker in `Running` for longer than the interval is not dead (a long kernel), it is reported in `sched.slow_task` at debug level. A dead worker terminates the run with `MorunaError::Kernel { stage, seq, msg: "worker <w> died outside apply" }` for its last task (a scheduler bug, never a kernel's fault, h failures).

**f.15 Knob handling (`Knobs::set`).** Clamp to the preamble's range: `MorselTarget.bytes` to `[morsel_min, morsel_max]`, `ActiveWorkers` to `[1, workers_max]`, `ReadAhead` to `[0, 64]`, `PromotionWindow.morsels` to `[1, 32]`; `HighWater.bytes` is passed as given; each clamp increments `SchedulerStats::knob_clamps` and logs `sched.knob_clamp` once per knob kind. Store `MorselTarget`, `ActiveWorkers` (unparking or letting workers self-park at the next loop head) and `ReadAhead` atomically; forward `StagingTrigger { stage, on }` to `placement.set_staging(stage, on)`, `HighWater { stage, tier, bytes }` to `placement.set_water(stage, tier, bytes / 2, bytes)`, and `PromotionWindow { stage, morsels }` to `placement.set_promotion_window(stage, morsels)`; record every forwarded value so `snapshot()` returns it (`KnobSnapshot.high_water`, `promotion_window`, contracts d.11). A `set` after the run has exited is a no-op (RC h).

**f.16 The run as a DAG (KA5, 2026-10-29).** `Pipeline { sources, kernels, sinks, topology }` (contracts d.16; `Pipeline::chain` is the linear chain) replaces the one source, chain and sink, and every rule above reads "the stage's input" as "each of its input queues", "its output" as "each of its output queues", "the source" as "each source" and "the sink" as "each sink". What changes, and nothing else:

1. **Validation (f.1).** `validate_graph` walks the stages in their numbered order (one in which every queue goes forward): a source's queues carry its schema; each stage's input ports are checked with `PayloadSpec::check` and its output is `Kernel::output_schema_of` of their schemas in port order, after `Kernel::max_inputs` admits their number; each sink's `accepts` is checked against its queue's schema, and the sink is opened with it. Checkpointing is off when any sink does not track commits or any source is not repeatable. `set_consumer` on every queue.
2. **Drives (f.5, f.6).** One source drive per source and one sink drive per sink, each idle until `run`. A source drive pushes each read into every queue its source gives, with one `push_to`, so the batch is shared (PL-I16); it holds back while any of its queues is full, while any sink's ordered buffer is stalled, or while one of its queues holds an evicted entry, which it replaces in that queue; its morsel target is its first queue's consumer's. A source's queues close when it is exhausted; the run's sources are exhausted when the last is.
3. **`pick` (f.3).** A stage is admissible when one of its input queues' heads is resident, none of its output queues is full, and an instance is free; among admissible stages the fewest output bytes (summed over its output queues) wins, ties to the higher stage; of that stage's resident input ports, the one whose queue holds the most bytes is served, ties to the lower port. A chain's stage has one of each, which is f.3 exactly. The adaptive scheduler (KD7) replaces this rule and reads the same DAG and queues.
4. **A task (f.2).** The worker pops the chosen port's queue and calls `Kernel::apply_port(state, port, payload)`. The output's number is `Topology::out_seq(stage, port, seq)` (the input's, for a stage of one input or one that joins its inputs by morsel), which is the number the trace record and a diagnostic carry, and the output is pushed with one `push_to` into every output queue of the stage. A stage that joins its inputs by morsel keeps what it pops until its number's set is complete (SC-I18), then calls `Kernel::apply_aligned`; a probe of one takes the other ports' heads itself, as the controller probes in stage order.
5. **Closing (f.7).** For each stage, the three reads in the same order over its input queues: all sealed in the engine, then all their counts zero, then `running`; then a join's incomplete sets are settled (SC-I18), a stateful stage is handed to a worker to finish (SC-I17), which closes its outputs after what its instances give, and any other stage's output queues close. The cascade looks at every stage, in order, while a pass closes one.
6. **Skips (f.8).** A skipped morsel is told to every sink it would have reached, by the number each would have given it (`Topology::to_sinks`), and each sink's watermark moves.
7. **Numbers a sink never receives (f.11).** A sink reached by more than one path, or through a stage of several inputs, may have numbers no morsel will have: past a shorter source's end in a fan-in. Its drive skips each such number (`Sink::skip`) once the sources it would come from are read to the end and the stages whose `finish` could give it have finished (`Topology::reaches` over `Topology::produced`, amended 2026-11-04), up to the highest number its queue has delivered, and, when all of that is known, up to the last a morsel can have there (`Topology::last_at_sink`); so its watermark, and an ordered sink's next expected number, move past them. A chain's sink has none and does none of this: the batches a chain's stages give at their ends are numbered one after another past the last source number, so it receives every number.
8. **Completion (f.6, f.10).** Each sink drive drains its queue and waits; the last to drain claims the exit and finishes every sink in order (`SinkCommitting`, `finish`, the watermark to its last number, `SinkFinished`), so a cancel or a failure still finishes none. `RunOutcome::Completed { sinks }` holds each sink's summary.
9. **Checkpoint and resume (f.12, f.13).** `CheckpointExtras` carries each sink's watermark and state and each source's cursor and issued reads. On resume each sink is resumed at its own watermark, which is also its **floor**: a morsel its queue delivers at or below the floor is dropped, because a resumed run replays a source morsel to every sink and this one had committed what it becomes here (placement f.17). Each source's drive re-reads its own `to_recompute` before issuing new reads.
10. **Probes (f.9).** A stage's probe takes the head of an input queue that holds a morsel; when none does, the source feeding one of its ports reads one for it, pushed to every queue that source gives.
11. **A stage's finish (SC-I17, 0.6.1).** The finish job holds the manifest lock while the instances finish, so the checkpoint thread waits for it rather than timing out on an instance, and holds a busy slot, so a checkpoint barrier waits for it. Once one `finish` has given a batch, no manifest is written for the rest of the run (f.12): the batch was read from no split, so no manifest could have a resume read it again. **Resume** follows the stateful kernel's rules (f.13): a run resumed from the last manifest before the finishes restores a `Checkpoint` stage's instances (or rebuilds a `Reinit` stage's with `init`), takes the rest of its input and calls `finish` again at its end; a `Reinit` stage's `finish` then sees only what came after the manifest, so a kernel that must see the whole run to give its result declares `resume="checkpoint"` (or `"forbid"`).
12. **Joins by morsel (SC-I18, 0.6.1).** The facade aligns such a stage in the topology (`Topology::align`, contracts d.16) and `validate_graph` refuses a kernel and a topology that disagree on it. The branches into it are ready at once and the workers take them at once, each on its own: a fan-out of `n` branches of one morsel runs in about the time of the slowest, not of their sum (PY-T46). The morsels a join keeps are held in the engine's catalog like any taken batch; how far one branch may run ahead of another is bounded by memory admission alone.

The facade's events (MH 4.3) read the same topology: `Fed { queue }` readies the queue's consumer, `QueueClosed` ends its producer at the first of its queues to close and drains its consumer when the last of its inputs closes, and sources and sinks are named by number.

**f.21 The stall detector (KD7b, SC-I12's backstop).** At every heartbeat check (f.14) the run is quiescent when it is live and not gated, no worker is busy, no read, write or move is in flight, no push is waiting for room (a waiting push ends itself after `PUSH_STALL`), no claim is outstanding, and some queue holds a batch. A signature of what counts as progress is kept: the catalog's releases, frees, spills, reloads, evictions and overflows, every stage's takes, every source's pushes and every sink's writes. Quiescent at two checks in a row with the same signature, no event can come that would move the run, so it ends with `Staging("no unit can make progress ...")` naming the resident bytes, the budget, and every queue's batches, bytes in memory and on disk, and head. It is not a timeout: a run whose units, IO or moves are slow is not quiescent.

**f.20 Claims and pushes (KD7b, SC-I12).** The wait is measured by `SchedulerConfig::clock` (`Clock`: `now` and `pause`; `SystemClock` in a run), so a test steps it. `admit_push(stages, morsel, claim)`: a claim in another tier than the batch's (a device output) is given back and a claim of nothing is taken; while the claim is short of the batch's bytes, the difference is reserved: granted, joined, and the batch pushed under it (`push_reserved`); pending, the push parks for a millisecond and tries again; refused, a share of the payload goes `push_spilled`, and when the run has no disk tier the push parks and tries again. A cancelled or ending run stops waiting with `Cancelled`; `PUSH_STALL` (30 s) without room ends the run naming the morsel, its bytes, the queues and the last refusal. A worker's output is pushed this way under the claim its unit ran under, after the unit has released its input, so a batch whose last consumer that was gives its bytes back first; a source's read and a probe's output are pushed with no claim of their own; a re-read for `replace` claims its bytes and waits the same way, and never goes to disk, because its consumer waits for it in memory. The worker acquires its stateful instance before it pops (f.4), so a lost race for an instance takes nothing.

**f.22 The cost model in the scheduler (KD7c; SC-I14, SC-I15; adaptive-runtime 9.4, 9.6).** `set_cost(online, keys)` keeps the models and the keys for the run. A unit's inputs are its head's bytes, its rows at the stage's measured rows per byte (before its first unit, its first port's producer's rows per byte out; unknown before anything has been made) and the active workers; `Online::predict` answers, widened for a drifting key. `contract` carries the deciding model's bytes out and duration (median, p95) into the port's `Prediction`, `drifting` when either is, and its observations the fewer of theirs. The claim cap is `budget - floor + batch`, the placement's floor at `morsel.min_bytes` (09 f.18 rule 13): the room the floor leaves for one unit's output. When a unit ran under a model's prediction and produced, the worker settles it (`Online::settle`) with the inputs it measured (rows and bytes in, the active workers) and its outcome (`Origin::Run`; wall and worker time, rows and bytes out). There is no peak-memory observation from shared-process endpoint samples: those samples cannot measure a unit's transient peak or attribute another worker's allocation to it. PeakMemory remains absent unless a separate, true adapter measurement supplies it; isolated warm-up can train that target. ABI account peak is the lifetime high-water charge of that account, not automatically one unit's peak. Predictions are cached by stage key version, input-size bucket (1/64 of a doubling), and the complete inputs passed to the model, including active workers and the currently known rows per byte. A cache hit allocates nothing; settling a key invalidates every stage sharing it. A worker-count change or new source statistics must be visible on the next prediction even before a unit settles. The dedicated learning thread flushes every 10 ms without holding the model/state lock across IO; the pending queue is bounded by SDD 24's `PENDING_LIMIT`. After output completion the run waits up to `DRAIN` (5 s by its clock) for the remaining flush and fitted-state save, then abandons the store with an explicit reason and exact written/unwritten accounting. `SchedulerStats::policy.learning` maps the learner's report to stages (a key's first stage).

**f.23 `residency_greedy` (KD7c; adaptive-runtime 9.4 step 2, G8; RA 9 (C)).** One step, no simulation. For each ready unit: `frees = (head bytes when its take is the batch's last, else 0) - (bytes out × the share of its output queues that feed kernel stages)`, over its predicted duration (the median; a drifting key's output at its 95th percentile); what a sink takes leaves at the sink's pace and needs no worker, so it does not count as held. With `p` the share of the budget resident or claimed (an empty budget is full), `score = (1 - p) · critical / most critical + p · frees / most |frees| + min(waited / bound, 1)`, `bound = AGE_LIMIT (16) × max(median, AGE_FLOOR_NS (1 ms))`. Units whose head has waited its bound go first, the longest wait first (G8: no ready branch waits more than 16 times its predicted duration); then by score; ties to the later stage, then the fuller queue, then the lower port. Every ready unit is in the order. Ready heads are resident by construction (f.3), so "inputs resident" decides nothing between ready units; residency enters as the memory a unit frees and adds.

**f.24 `lookahead` (KD7c; adaptive-runtime 9.4 steps 3 and 4, G12; RA 9 (D); 24 f.13).** The ready units in `residency_greedy`'s order; with fewer than two, that order. Otherwise the snapshot: every source and kernel stage a task, in that order; from the last stage back, a producer has finished what each of its consumers has started and holds in its backlog (each port's batches, at most `HORIZON_BATCHES` (8)); a source's units are what it has read (it reads nothing more: the horizon is draining what the run holds), a stage's what it has started, its backlog and what its producers have still to make; a stage's unit costs its prediction (time a worker's, output and reservation its bytes out held to the claim cap), a source's nothing and its batches' mean bytes; each unit under way has its median less what it has run left; the last batches of a backlog are on disk in the share the queue holds on disk, never one a unit under way holds; a stateful stage is serial; the machine is the run's (workers at least the units under way). The simulator for that workload is kept, and resized when only the machine changed since the last decision (24 CM-I24); else built. Each of the first `WIDTH` (3) units is played first, at medians from the snapshot (24 CM-I23), the rest by the critical path (of the units that fit, the task with the most work still to start on the longest path from it, over its cap; ties to the later task); then the best `BEAM` (2) are played with each of the `WIDTH` as a second step, and a first step is worth its best sequence. A drifting ready unit makes it one step deep. Before each simulation, the time it is expected to take (the last ones', smoothed; 20 µs before any) must fit what is left of `budget_ns`, or the decision stops and counts `shallower`. The first step of the earliest finish runs, ties to the greedy order, then the rest in the greedy order. A snapshot or simulation that fails is counted with its first reason (`PolicyCounters::simulation_error`) and the greedy order answers.

## g. Concurrency within the component

Lock order (preamble 4.2): the stage table lock (position 1) is taken only during startup, `init_instances` and stage close; instance pool mutexes (part of position 1 by convention); the placement queue lock (position 2) is taken inside the engine's `pop`/`push` and never held by the scheduler across `apply` or across any call into another component. The stats cache is atomics plus a timestamp. Workers park on per-worker `crossbeam::Parker`s. The two drives are threads created by `new` and started driving by `run` (`std::thread`), not workers and not reactor threads: they are the only non-reactor threads that wait on a `Completion` (contracts CT-I7, RE-I2), they hold no scheduler lock while waiting, and they exchange requests with the probe and the checkpoint thread over `crossbeam` channels. The checkpoint thread and the heartbeat checker read the heartbeat table without locks. The `RecordHook` runs on the recording worker after the trace channel push (position 5), with no scheduler lock held.

## h. Behaviour

**Normal path.** `new` validates and opens; `init_instances` fills every pool; the controller samples the baseline and probes each stage through `Prober` (one worker active per probe); the controller sets initial knobs; `run`: drives and the checkpoint thread start; the source drive fills Q0 to high water, workers pick stage 1, outputs fill Q1, workers spread across stages by the emptiest-output rule, the sink drive drains Qn; source exhausts; queues close in order; sink finishes; `Completed`.

**Edge cases.** Zero splits: Q0 closes immediately; queues close in order; sink `finish` writes an empty output; `Completed`. Splits with no rows, anywhere in the plan or making up all of it: never read, stepped past by the cursor (f.5); a plan whose splits all hold no rows ends as zero splits does (SC-T24, SC-T25). Zero kernels (`kernels=[]`, 12 h): allowed; there are no stages, no probes (the controller sets `MorselTarget { stage: 0 }`, RC f.3) and no instance pools; the source drive reads at `morsel_target[0]` and the sink drive pops Q0; workers stay parked for the whole run; the chain check is the sink's `accepts` against the source schema. One stage, stateless, identity kernel: workers alternate stage 1; the emptiest-output rule is trivial. All workers parked (`active = 0`, controller bug): impossible after clamping (f.15, min 1). A kernel that returns a payload in a tier the next consumer cannot accept: placement handles it (promotion); the scheduler does nothing. `read_ahead = 0`: the floor of one read (f.5). A single row larger than `morsel_max`: passed at its natural size (f.5, SC-T17).

**Failures.** Source read failure: `Terminating` with the split named (there is no skip for source errors); a single row larger than the budget fails the read with `Alloc` and terminates with the split and row range in the diagnostic. Stateful `init` failure: `init_instances` returns the error and the facade never calls `run`; nothing has been read or written (SC-T18). Sink write failure: `Terminating` with the sink error; in-flight writes complete or fail; `finish` not called; the sink's own cleanup runs on drop. Placement `pop_blocking` returning `Err(Staging)` for a head that cannot be produced: `Terminating` with the placement diagnostic. Worker thread death outside `apply` (a scheduler bug): the heartbeat checker (f.14) terminates the run with an internal error rather than hanging (SC-T19). A drive that panics (amended 2026-10-28, MA2), in a source's `read` or its future, in a sink's `write` or its future or `finish`, or in the drive's own code: the panic is caught on the drive thread and the run is terminated, the source drive's with `Source { split, msg }` naming the split of the oldest read it had issued and not pushed (the split at the cursor when none was) and the sink drive's with `Sink`, each message saying `the source drive panicked:` or `the sink drive panicked:` (`the sink panicked in finish:` for `finish`, caught inside the exit claim that `finish` holds) and what the panic said. Before this the drive thread died, nothing published an exit, and the run waited for ever with every task unended (SC-T26). Sampler failure: the sampler never fails after construction (DS-I3); the controller decides when to terminate on read errors (RC h) through `Knobs::terminate`.

## l. Implementation notes for the agent

Environment facts to verify before starting: `rustc --version` matches `rust-toolchain.toml`; whether a container runtime honouring `--memory` and `--cpus` exists on this host, since SC-T12 and the wave 4 gate need one and the weekly CI job supplies it otherwise; `libc::CLOCK_THREAD_CPUTIME_ID` is present, which `cputime.rs` needs to attribute worker busy time. (Added 2026-09-22: this section had no such list, which the hand-off protocol requires of every component.)

Decisions the PM took on 2026-09-22, on the component 10 agent's report:

f.3 and f.4 describe the instance rule that broke SC-I6, and the corrected rule is this. An instance has a home worker, set by `init_instances` (or `restore`) and claimed on first acquire when unset, and a borrow never moves it: the original text set the owner on every acquire, so one borrow moved an instance's home for the rest of the run and the worker that had been warming it lost it, which cascaded until every worker had run every instance and affinity sat at about 85 percent against the 90 the invariant requires. And f.3's admissibility must read "the worker may be handed one of this stage's instances", not "some instance is free": with the looser rule, eight workers competed for four instances and the home meant nothing. A worker may serve a stateful stage when it owns a free instance, or when a free instance's home lies outside the active worker count, so that lowering `workers.active` still releases instances. Measured after the fix: 600 applies over four threads, one instance each, no switches, affinity 100 percent, with no throughput traded, because four instances cap concurrency at four either way. SC-T6 keeps section k's 0.9 threshold and gains the assertion that would have caught this: with more workers than instances, each instance is run by one worker, which a run at 90.1 percent with an instance wandering across eight workers does not satisfy.

A run's ending is claimed before any side effect (f.10). The sink drive could finish the sink and then lose the race to publish the outcome, so a cancelled run showed `finish_calls == 1` against f.10, about one run in thirty.

A resume gap the same work uncovered, not fixed and not to be worked around: f.5 records the source cursor as "the next range to issue", so a read in flight at a checkpoint is in neither the manifest's lineage nor the future reads, and that morsel is lost on resume. The cursor must be the oldest range not yet pushed, in the real engine as much as in the fake. It is an E12 item, because it weakens a resume guarantee, and it is written here so the facade's resume path (12 f.7) and the wave 4 integration closure do not rediscover it as a mystery.

One trade to know, taken deliberately: a home worker busy on another stage leaves its instance idle even when a free worker exists. Affinity was chosen over instantaneous utilisation, because an instance is a loaded model and the thrash is what instance pools exist to avoid; widening the borrow rule is a one line change if a later measurement says otherwise.

A worker pops with the contract's non-blocking `pop`, not `pop_blocking` as f.2 says. A worker's claim on its stage has to bracket the pop, or f.7's cascade closes an output queue under a morsel about to be pushed into it and the run completes with that morsel stranded, against SC-I9; holding the claim across a blocking call deadlocks the cascade instead. The agent found this through SC-T9 failing once in twenty runs, which is the kind of defect that ships when a test is run once. One consequence to know: `placement_miss_wait_us` is 0 for a worker task, because the worker no longer waits, and the engine's own `QueueStats` is where a miss is counted.

`sink.concurrency` does not bound an ordered sink (f.6). A `ReorderBuffer::write` future does not resolve until the morsel's turn, so a held morsel would hold a slot and the drive could never pop the sequence the buffer is waiting for; for an ordered handle the bound is the buffer's own byte limit, reported through `is_stalled`.

SC-I8 says a skipped morsel is recorded with `Outcome::Error`; contracts d.13 defines `Skipped` for exactly this and SC-T7 and SC-T14 assert it. The contracts win: a skipped morsel is `Skipped`, and SC-I8's sentence is wrong.

f.8's device out of memory retry cannot be written as specified, because `Kernel::apply` takes the payload by value and an `Err` returns nothing to retry with. The scheduler records the failure so the trace keeps one record per morsel per stage (G-I4) and applies the error policy. Closing the gap properly means either dropping the retry from f.8 or having `apply` hand the payload back on error, which is a contracts change and waits for a host with a device to exercise it (E1).

No knob carries the sizer to the scheduler, so `TraceRecord::sizer` is written as 0 (rule) on every record; the run report should take the sizer from the controller's summary instead, which is where it is known.

Files: `src/lib.rs`, `src/pipeline.rs` (validation, f.1), `src/worker.rs` (e.1, f.2, the heartbeat writes), `src/pick.rs` (f.3), `src/instances.rs` (f.4 `init_instances`, and the restore path of f.13), `src/source_drive.rs` (f.5, the cursor, the helper requests of f.9, the recompute pass of f.13), `src/sink_drive.rs` (f.6, f.11, the heartbeat check when checkpointing is off), `src/lifecycle.rs` (e.2, f.7, f.10, `run`, `run_resumed`, `apply_resume_point`, `shutdown`), `src/policy.rs` (f.8, `terminate`), `src/checkpoint.rs` (f.12, the checkpoint thread, `checkpoint_now`, the heartbeat check when checkpointing is on), `src/heartbeat.rs` (f.14), `src/probe.rs` (f.9), `src/knobs.rs` (f.15, atomics, `snapshot`), `src/stats.rs` (`StatsSource`), `src/cputime.rs`. `unsafe` is permitted only in `cputime.rs`, for the single `libc::clock_gettime(CLOCK_THREAD_CPUTIME_ID)` call behind a safe `thread_cpu_ns()` (`// SAFETY:` a valid out-pointer to a `timespec`); nowhere else outside tests (E9). `catch_unwind` around `apply` requires kernels to be `UnwindSafe`; wrap with `AssertUnwindSafe` and document that a panicking kernel's state is retired.

The drives poll the `BoxFuture`s that `Source::read` and `Sink::write` return with a minimal single-future executor (a `Waker` over the drive's `Parker`); the futures inside await `Completion`s, which implement `Future` (contracts d.9). No tokio dependency in this crate.

Anti-patterns: no central dispatcher thread; no worker holding a placement lock across `apply`; no trace record built anywhere but `worker.rs` and `probe.rs`; no `unwrap` on `pop` results; no public `checkpoint` method; no local definition of a type the contracts define.

### Portable checkpoint barrier

A prepared portable manifest hook first acquires its actual charged encoding/IO resources while the run can release memory. Only then does it acquire the atomic control lease shared with probing, close worker admission, and ask each original source/sink drive to pause. Each drive keeps polling its own admitted futures and acknowledges only after its last result has reached placement or its sink. No reactor completion or future changes owner. Workers must hold no busy slots before the checkpoint states and resident payload references are observed. Ordinary local checkpoints retain their existing in-flight lineage contract.

The barrier has a bounded deadline and resumes all gates on failure, cancellation, or return. An ordered write needing unavailable input may prevent a stable checkpoint; this is an explicit refusal, never a reason to discard that write or report a partial checkpoint complete. Probe and portable checkpoint control operations cannot open one another's admission gates. Publication must finish under its own bounded deadline and a local-only acknowledgement is diagnostic pending state, not portability.
