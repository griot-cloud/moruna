# 4.4: `group_aggregate`, with a hash path and a dense path

- **System design:** `architecture/moruna-os-system.md`, sections 4A, 4B, 4C (accumulate, merge,
  finish), 4G.4. **Needs:** 4.1's formats. **Rules:** `architecture/work/_rules.md`.

## Build

1. **The specification:**
   - aggregates count, sum, min, max and mean, with sum's overflow rule stated;
   - keys of any fixed-width type and strings;
   - the dense path is taken when the job declares the key domain and it is small;
   - output order is stated; empty input is stated.
2. **The CPU reference** under `KernelKind::Stateful`:
   - each instance accumulates;
   - `finish` gives its partial result;
   - partial results merge by a stated rule, so instances can run on every CPU (6.3e).

   It reports its state's size through `KernelState::footprint`. The hash path and the dense path
   sit behind one signature.
3. **The corpus,** including Occupancy's counting step (`bench/vm/workloads.py`) after its expansion.

## Measure (4G.4)

On Occupancy's real keys (zone × minute of day, at most 432,000 cells), on a month: the dense
path against the hash path against `np.unique`, with the Mac's load recorded.

## Success

- Occupancy, written as today (expand, then count through `group_aggregate`), gives 0.6.6's rows
  on a month.
- The measurement, and coverage of 80% or more.

## Report

The spec, both paths, the merge rule, the corpus, the measurement, coverage and the commits.
