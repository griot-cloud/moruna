# 5.0: Rust's standard library on Moruna

- **System design:** `architecture/moruna-os-system.md`, section 5A0.
- **Needs:** nothing. **Rules:** `architecture/work/_rules.md`.

## Goal

An ordinary Rust program with `std`, using arrow-rs, builds for Moruna and runs as a native task.

## Build

1. **The target:** `kernel/targets/x86_64-moruna.json`, from `x86_64-moruna-user.json` with
   `"os": "moruna"`, `"std": true` and the same code model, relocation and features.
2. **`std`'s platform layer:** a copy of Rust's `library/` for the kernel's pinned nightly
   (`nightly-2026-07-21`, from its `rust-src` component), in `kernel/vendor/rust-std`. Its README
   names the toolchain and the SHA-256 of every file changed, and every change is marked `moruna:`.
   Add `target_os = "moruna"` beside an existing small platform (Rust's `motor` or `hermit` layer
   is the model; say which you follow), implemented over `moruna_sys`:
   - `alloc`: the process heap `moruna_sys` already provides;
   - `thread`: spawn, join, sleep and yield, with thread-local storage;
   - `sync`: futex-based `Mutex`, `Condvar`, `RwLock` and `Once`, over the core's futex calls;
   - `time`: `Instant` from the clock page; `SystemTime` from the realtime base, or unsupported
     when it is unset (1.8);
   - `random`: from the core's random call (`moruna_svc::random` uses it);
   - `stdio`: stdout and stderr as lines into the task's log (`moruna_sys::plane::Log`), and stdin
     empty;
   - `env` and `args`: from the start page;
   - `fs`, `net`, `process`, `pipe`: unsupported, every call answering `Unsupported`;
   - panics abort and print their message to the log.
3. **Building with it:** `kernel/tools/build-std.sh` builds a program for the target with
   `-Zbuild-std=std,panic_abort` and `__CARGO_TESTS_ONLY_SRC_ROOT`, or the documented way to point
   build-std at a source tree.
4. **The proof program:** `kernel/examples/std-arrow`. It makes Arrow arrays, runs a compute kernel
   (`sum`, a `filter`, a `sort`), writes and reads them as Arrow IPC in memory, spawns two threads
   that share a `Mutex`, and prints the results.

## Phase 1, host and build

- The target and the patched `std` build. The proof program builds for `x86_64-moruna`.
- Host tests of the platform layer's pure logic (the futex lock's state machine; time arithmetic).
- `cargo deny` on what the proof program pulls in.

## Phase 2, booted

The proof program, added to the cloud profile as a task the supervisor starts in a test image
profile (`cloud-test`, as 2.2c defines it), prints its results on the console under the emulator.

## Not yours

The function SDK (5.1), files and sockets, anything in the core beyond what the layer needs. If
the layer needs a new core call, stop and ask.

## Report

The commits, the platform you modelled on, every changed `library/` file with its line count, the
proof program's output, and the build time.
