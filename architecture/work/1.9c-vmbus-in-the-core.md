# 1.9c: VMBus in the core, and the `vmbus` process

- **System design:** `architecture/moruna-os-system.md`, section 1F ("VMBus, split by the microkernel
  rule").
- **Needs:** 1.8 and 1.9b merged. **Rules:** `architecture/work/_rules.md`.

## Goal

On Azure, the node lists the devices Hyper-V offers it over VMBus, and a driver can open a channel.

## Build

1. **The core:** when Hyper-V is found (1.8), it enables CPU 0's SynIC with SINT 2 at a vector of
   its choosing, and makes the boot capability `root.hyperv` with exactly 1F's six calls. A new ABI
   minor, with the calls documented in `kernel/abi`. Hyper-V's constants come from `hvdef`.
2. **The calls' rules:**
   - a message posted is at most 240 bytes;
   - a signal handle names one connection ID, can't be widened, and can be given to a driver;
   - `take a message` never blocks, and the interrupt object is how a caller waits;
   - only the holder of `root.hyperv` can post, take or map. A signal handle can only signal.
3. **The `vmbus` process:** `kernel/drivers/vmbus/server`, a program on `moruna-svc` wiring
   `moruna-vmbus` (1.9b) to those calls, serving `moruna.driver.vmbus` to drivers:
   - list the offers of an interface ID;
   - open a channel, giving the driver its rings' memory object, its signal handle and a wake
     word;
   - share memory with the host;
   - close.

   The protocol's types live in `kernel/drivers/vmbus/protocol`.
4. **The cloud profile:** `devices` gains nothing. The supervisor grants `root.hyperv` to `vmbus`
   when the boot information says Hyper-V. On other machines `vmbus` isn't started.
5. **Counted:** the kernel-mode lines and calls this adds, in `architecture/data-os.md` section 0.

## Testing

- Host tests of the protocol and of the server over a fake `Hv`.
- **Booted on Azure:** item 1.7b's setup in `griot-dev` (one `Standard_D2s_v4`, zone 3, the item's
  resource group, deleted after). The console lists each offer's interface and instance IDs.
  Creating it is approved for this item: at most two machine-hours in total.

## Success

The console lists Azure's offers, at least the SCSI controller and the network card; the host tests
pass; the counts are written down.

## Report

The commits, the console log, the counts, and the resources created and deleted.
