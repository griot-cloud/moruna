# 6.3z: a ring task stamps each piece's function time on its release

- **System design:** `architecture/moruna-os-system.md`, section 3A (the engine sizes from what a
  run observes; the cost model) and SDD 29 (the plane). **Rules:** `architecture/work/_rules.md`.
- **Needs:**
  - 6.3m, merged at 177cb394: `apply_morsels`, `Completed`, `MorselTime::{Unit, Given, Untimed}`,
    and `layout::Morsels`;
  - 6.3p's clock page, `moruna_sys::datapath::clock_now` and `RingCalls::clock`.
- **Found by:** 6.3m. No ring task reports a piece's time: `Event::Put` and `Event::Released`
  carry none, so every ring morsel is `Untimed` and ring stages teach the cost model nothing. An
  engine-side stamp was refused, because under pipelining the engine's worker is away between
  units.

## Decided (PM, 2026-11-19)

1. **The task measures it.**
   - In the task's plane library (`kernel/sys/src/plane.rs`, `Rings`), the time of a piece runs
     from the task taking the batch off its input ring to its release of it, read on the clock
     page.
   - Its waits for a free window (`wait_window`) are subtracted, because they are the engine's
     time, not the function's.
   - It is reported as both wall and CPU nanoseconds, since a piece is the task's own
     single-threaded work between those two points.
2. **The release carries it.**
   - The input ring's release entry gains the piece's nanoseconds. If the entry has no room, the
     ring's layout version rises.
   - Both directions stay compatible:
     - an engine reading an older task's release sees no time;
     - an older engine ignores the field.

     Test both, as 6.3p's sim tests do for old and new.
3. **The plane gives it.** `Event::Released` gains `piece_ns: Option<u64>`, in the kernel plane
   (`kernel/plane/core`) and in the Linux plane (`crates/moruna-plane-linux`) alike.
4. **The stage sums it.**
   - `layout::Morsels` keeps each morsel's summed piece times.
   - A completed morsel whose pieces all had a time is `MorselTime::Given { wall_ns, cpu_ns }`,
     the sums; any piece without one makes it `Untimed`.
   - The warm-up's pieces and a restart's re-posted pieces are timed as they ran, not counted
     twice: a piece posted again replaces its earlier time.
5. **No constant, no estimate.** A time that is missing stays missing.

## Refused

- The engine stamping posts and releases.
- A time inferred from the unit's wall.
- A per-stage average spread over morsels.

## Done when

- **Host tests:**
  - the plane's sim gives a piece's time, with a window wait subtracted;
  - an old task gives `None`;
  - `layout::Morsels` gives `Given` when every piece is timed and `Untimed` otherwise;
  - the scheduler's cost model gets observations from a ring stage (6.3m's model, now with the
    real path);
  - the existing plane, micro, scheduler and runtime tests pass.
- **Coverage:** at least 80% of the lines added.
- **Clippy:** x86_64 clean, `x86_64-moruna-user` included where the plane library builds for it.
- **The PM's part:** rebuilding the gate tasks at the merged commit and booting the node check.
