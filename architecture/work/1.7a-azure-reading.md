# 1.7a: Azure findings, the reading half

- **System design:** `architecture/moruna-os-system.md`, section 1F.
- **Needs:** nothing. No code and no cloud resources.

## Goal

Answer, from source and documentation, three of 1F's four questions, so the PM can make 1F final.
The fourth, how far the core boots on Azure, is the booted half and is not yours.

## Build

Write one note, `architecture/work/1.7-azure-findings.md`, that answers:

1. **Which old PC devices does the core touch,** at boot and while running? Read
   `kernel/vendor/ostd-0.19.0/src/arch/x86` (boot, timer, irq, the ACPI and TSC code) and
   `kernel/core`. For each device or table (PIT, PIC, HPET, CMOS clock, I/O APIC, serial ports,
   the ACPI tables read): the file and line, whether an Azure Generation 2 machine has it, and
   what Hyper-V offers in its place. Cite Microsoft's documentation for each claim about Azure.
2. **What does the core need from Hyper-V** to reach `services started`? List each piece (finding
   the hypervisor, the clock rate, the timer, the hypercall page, the message and event pages,
   the VMBus interrupt), with the place in Microsoft's Hyper-V specification that defines it.
3. **What does Microsoft's OpenVMM offer** (github.com/microsoft/openvmm)? For guest-side VMBus,
   storvsc, netvsc and MANA code: the crate, what it does, its licence, and what it depends on
   (std, an async runtime, Linux). Say plainly whether each can be used in a Moruna driver
   process, adapted, or only read as a reference.
4. **Sizes for items 1.8 to 1.12:** small, medium or large, each with its reason and its biggest
   risk.

Mark every statement as read in source, read in documentation, or your inference.

## Success

- Nothing in the repository changes except the note.
