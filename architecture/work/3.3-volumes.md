# 3.3: Volumes by serial

- **System design:** `architecture/moruna-os-system.md`, section 3C.
- **Needs:** 3.2. **Rules:** `architecture/work/_rules.md`.

## Goal

A job reads and writes the cloud volumes attached to the node, named by their serial.

## Build

1. **Serials:** `devices` reads each block device's serial (virtio-blk's `VIRTIO_BLK_ID`; Azure's
   come with 1.10) and lists them with their size.
2. **Grants:** `node-admission` resolves each `disk://<serial>` the job names, and grants the engine
   that device: read-only for a source, read-write for a sink. An unknown serial, or the boot disk,
   is refused at `validate`.
3. **The file layer on a volume** is today's `disk://` support (stream D). No new format.

## Success

On a booted node with two extra virtio disks given serials in QEMU (`serial=` on the device):
- one month of NYC taxi data on the first; the Score job writes to the second; the rows match
  0.6.6's for that month;
- a job naming the boot disk, or a missing serial, is refused at `validate`;
- a source volume cannot be written (a test sink pointed at it is refused).

## Report

The commits, the boot log, and the row check's output.
