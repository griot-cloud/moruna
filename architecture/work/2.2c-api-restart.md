# 2.2c: Restarting `api`

- **System design:** `architecture/moruna-os-system.md`, sections 1B and 2B ("If `api` dies").
- **Needs:** 2.2b. **Rules:** `architecture/work/_rules.md`.

## Goal

When `api` dies, the node keeps running and `api` comes back, as the OS design requires.

## Build

1. **The supervisor** restarts `api` only, at most 5 times in 10 minutes. A sixth death is
   `moruna: fatal api: ended 6 times in 10 minutes` (1B's form: the stage is the service's
   name; PM, 2026-11-18), then the stop of 1B. Every other
   service's death stays fatal.
2. **The listener:** `network.conf` gains `grant listen-supervisor rights=grant local=0.0.0.0/0@443`.
   `node.conf` links it to the supervisor. At each `api` start, the supervisor mints `api`'s
   listener channel with `Client::grant`, with the policy of 1.3's `listen-api` grant, and gives it
   to `api` as its `network` slot. 1.3's `link network listen-api api network` line goes. If the
   node config grammar cannot link a service to the supervisor itself, ask.
3. **The hand-over:** at each `api` start, a fresh channel pair; `api` gets one end. `platform` gets
   the other over a new supervisor-to-`platform` control channel, as one message,
   `api-restarted`. `platform` then sends its stored hand-over again.
4. **The console:** `moruna: service api restarted (<n> of 5)`, then `api`'s new `tls` line when it
   made its own identity.

## Testing

A node has no way in but the API, so the test kills `api` from outside the node's design: a build
of the cloud profile for tests only, where `api` exits when it receives a request to
`/v1/test/exit`. That build is a separate image profile, `cloud-test`, never the release image.
Say so in the profile file.

## Success

- Booted with `cloud-test`: three exits in a row; after each, the restart line, a new `tls` line,
  and `health` answering again within 5 s.
- A sixth exit within 10 minutes powers the node off.
- The release `cloud` profile builds without the test route; a host test proves it.

## Not yours

Restarting any other service.

## Report

The commits, the boot log, and the timings.
