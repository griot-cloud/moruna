# 1.5: Image formats and the OpenStack recipe

- **System design:** `architecture/moruna-os-system.md`, sections 1A and 1E.
- **Needs:** 1.1. **Rules:** `architecture/work/_rules.md`.

## Goal

The one raw image becomes each cloud's format, each format boots, and the steps to put the node on
Servercore are written down exactly.

## Build

1. **`package.py --formats`** takes a list of `raw`, `qcow2` and `vhd`, and writes each beside the
   raw disk:
   - `qcow2`: `qemu-img convert -O qcow2`;
   - `vhd`: a fixed-size VHD, `qemu-img convert -O vpc -o subformat=fixed,force_size`, from the raw
     disk rounded up to a whole MiB.

   Each output's size and SHA-256 are added to the package's evidence file.
2. **`uefi-boot.sh`** takes the format of its boot disk as an argument.
3. **`kernel/node/OPENSTACK.md`:** every command, in order, with the `openstack` command line,
   cloud `servercore`:
   - upload: `image create` with `--disk-format qcow2 --container-format bare` and the four
     properties of 1E;
   - a security group with one rule, TCP 443 inbound;
   - a server from the image, with node config as `--user-data`, on the external network, with the
     smallest flavor of 1 CPU and 1 GiB or more;
   - reading the console log;
   - deleting everything that was created.

   Mark every value the operator fills in. The node config in it carries no secret (1D).

## Success

- The qcow2 and the VHD each boot with `uefi-boot.sh` to `services started`.
- A host test checks that the VHD's size is a whole MiB and that its footer says fixed.
- The recipe is complete, and nothing in it has been run.

## Not yours

Running any `openstack` command, the Azure recipe (1.13), Secure Boot.

## Report

The commits, the boot logs, and the recipe's path.
