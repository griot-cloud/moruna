# 1.6c: After a fatal line, the node holds 60 s before it powers off

- **System design:** `architecture/moruna-os-system.md`, section 1B (Failure). **Rules:** `architecture/work/_rules.md`.

## Why

1.6b found that OpenStack serves a guest's console log only while the guest runs, and shows SHUTOFF 15 s late. A node that powers off a few seconds after its fatal line leaves nothing readable on Servercore, so the cause can't be seen.

## Build

1. After the first `moruna: fatal` line, the supervisor (or wherever 1.2 put the S5 power-off) keeps the machine halted for 60 s, then powers off by S5 as today. Consequence lines may still print during the hold.
2. The hold's length is one named constant with this item's reason in its comment.
3. Tests: a host test of the sequence (fatal line, hold, power-off) where the code allows it. Update the QEMU checks that wait for power-off after a forced fatal (1.2's tests and CI's boot checks) so they still pass. Their timeouts may need the 60 s added.

The commits, the tests, and the checks you changed.
