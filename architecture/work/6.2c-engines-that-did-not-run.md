# 6.2c: four engines never ran, the node's CPU is not measured, and a run cannot be repeated in part

- **System design:** `architecture/moruna-os-system.md`, section 6 (6A, 6B). **Rules:**
  `architecture/work/_rules.md`. Agents create nothing in any cloud: the PM runs the benchmark.
- **Found by:** 6.2 run 3 (2026-11-18, `bench-run3/bench/node/results/202611181311/`). The batch
  states are in `~/moruna-data/bench-run3-evidence/setup.json` and `runs.json`.

## The misses

1. **Ray and Dask were not installed.** `setup.json` says
   `"installed": {… "ray": false, … "dask": false}`. `install.py` puts every engine on CPython 3.14
   (`PIP`, "3.14+gil"). Every Ray and Dask run then exits 1 within 0.05 s of CPU.
2. **DuckDB and Spark were installed but fail:** exit 1 after 0.6 s (DuckDB) and about 20 s (Spark).
   Their stderr did not reach the batch state (`runs.json` has an empty `stderr`), so the cause is
   not known from the Mac.
3. **The node's CPU seconds show 0.0** for every Moruna row, so the CPU column cannot compare.
4. **A run cannot be repeated in part.** After a fix, or with a new node image, the whole plan
   (250 runs, about 5 h) would run again.

## Do

1. **Each engine on the newest CPython it supports,** found by trying to install it, with the
   version and the GIL state in the table, as today. Write in 6B why one interpreter for all could
   not hold. Ray, Dask, DuckDB and Spark install and import in a Linux x86_64 environment, and the
   setup refuses to go on if any engine in the plan did not install.
2. **A failed run's own error reaches the batch state and the table:** the last lines of the
   engine's stderr, kept in `runs.json` and shown on the table's line for that run. Then make
   DuckDB's and Spark's runs pass in a local Linux environment against a small Parquet file in a
   local Blob emulator (Azurite) or a stand-in. Fix the cause in setup: the DuckDB azure extension
   installed ahead and loaded from `ROOT/duckdb-ext` with no download at run time, and Spark's
   hadoop-azure resolved ahead.
3. **The node's CPU seconds** come from what the node reports for a job, if it reports it. Name the
   field. If it does not, write that down and ask the PM.
4. **`run.py --engines a,b,…`** runs only those engines' runs of the plan, into a new results
   folder. `--table` then merges any number of results folders, newest per run. A rerun of the
   four Linux engines, or of the node with a new image, then needs no repeat of the rest.
5. **Tests** for each, and a dry run of `--engines ray,dask,duckdb,spark` and `--engines moruna-node`.

## Report

The causes found for DuckDB and Spark, the fixes, the tests, the dry runs, and the commands.
