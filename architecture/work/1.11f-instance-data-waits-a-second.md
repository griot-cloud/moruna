# 1.11f: platform waits out a whole retry second after the lease

- **System design:** `architecture/moruna-os-system.md`, sections 1C (network) and 1D (`platform`,
  instance data). **Rules:** `architecture/work/_rules.md`, and 6.3's steps: diagnose and write the
  defect as a test, then fix.
- **Found by:** 1.11c's trace run 4, 11 Azure boots (`~/moruna-data/boot10/moruna-trace4/consoles/`).
  The files are cumulative: split them on `netvsc: … connected to the device manager`.

## The miss

In boots 1875, 2833 and 4825 the first ARP after the DHCP ACK goes out about 1 s after the ACK,
with nothing sent between. Boot 1875: the ACK at 330 ms and the ARP at 1322 ms on netvsc's clock.
In all 11 boots, boot_ms minus the ACK is 0.48–1.55 s.

`kernel/node/platform/src/instance.rs` `find`: a request with no answer is made again
`RETRY_NS` (1 s) after it began. A request begun before the interface has an address fails at
once, so the next one waits for the rest of the second, even when the lease comes a few
milliseconds later.

## Do

1. **Confirm it** from the consoles and the code: when `platform`'s first request begins, how it
   fails before the lease, and when the next one begins. Name any other fixed waits on the path
   from the lease to `ready` with their times: the TCP SYN retry, ARP, and Azure's wireserver.
2. **Write the defect as a test:** a request that cannot begin for lack of an address is made as
   soon as the address is bound, not a retry interval later.
3. **Fix it with an existing mechanism:** `platform` waits for the interface's address, as the
   `moruna: network wan` line already knows it, rather than polling. Name the mechanism you use
   (an address event from the network server, or a connect that waits for an address within its
   deadline), and ask the PM before adding a protocol. The 1 s retry stays for requests that were
   sent and got no answer.
4. **Report what a boot then costs** on the trace data, by computation. The PM measures it on Azure.

## Refused

A shorter `RETRY_NS`; any constant tuned to these boots.

## Report

The confirmation, any other fixed waits found, the test, the fix, coverage and the commits.
