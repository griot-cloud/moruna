# 6.3s: a run reported Completed lost a row group

- **System design:** `architecture/moruna-os-system.md`, sections 3A (the arena, memory) and 6 (the
  engine's correctness). **Rules:** `architecture/work/_rules.md`.
- **Found by:** 6.3d's wide-table tests (agent aec78710bd47181ae, 2026-11-18).

## The miss

A 768-column table of 40,000 rows was copied in the debug test process, at a named budget of
604 MiB, leaving an arena of 73.5 MB. The run ended `Completed`, with a peak at 0.77 of the
ceiling. The output read back 35,000 of the 40,000 rows: one row group was missing. No error was
reported.

The same table in a release build kept failing its arena reservations and retrying. It decoded for
132 s per worker and never finished, so it was cancelled at 10 minutes.

The appender reserves two arena buffers per column per morsel (`moruna-sources` parquet
`append.rs`, `Appender::reserve`). The arena's smallest class is 64 KiB (`moruna-arena`
`classes.rs`, `GRANULE`). A read of 768 columns therefore needs 96 MiB of arena, which is more
than this arena holds.

6.3d now makes the arena's least hold one such read, so 6.3d's tests no longer reach this state.
The loss itself is not 6.3d's, and it must be found here.

**Candidates** (unconfirmed): a failed arena reservation whose read is dropped instead of retried
or failed; a file lost at the sink; or a morsel or row group counted done without being written.

## Do

1. **Reproduce it.** The test is 6.3d's `a_wider_table_is_refused_then_held_at_the_least_budget`
   (`crates/moruna-runtime/tests/writer_heap.rs`), as committed on branch `work/6.3s-repro`. Run it
   against feature, with the arena's least as it was before 6.3d. Find the exact path that loses
   the row group, and write it as a host test of its own, as small as it can be.
2. **Fix the root.** A run either writes every row it read or ends failed, naming what it lost. No
   path may report `Completed` with fewer rows. Find every path of the same kind (a dropped read, a
   dropped morsel, a part not written) and close each one.
3. **Add the invariant as a check the engine keeps:** rows read against rows written for a map
   job, checked before `Completed` is reported. Count it per job, not per test. Say what the check
   costs.
4. **List** each path found, and its test.

## Refused

A fix that only makes the arena big enough. The loss must be impossible at any arena size.

## Report

The reproduction, the root, the fix, the paths list, the invariant's cost, coverage and the
commits.

## Lead (read from the code, 2026-11-18; not yet confirmed by a run)

The root is in feature's scheduler, `crates/moruna-scheduler/src/source_drive.rs`, not in 6.3d's code.

- A read that resolves `Err(Alloc)` leaves `inflight` and waits in `waits.retry` (`poll_inflight`).
- The cursor is already past its range (`take_next_range`).
- `close_when_exhausted` checks only `inflight` and the cursor, never `waits.retry`. It therefore closes the source's queues while the retry waits.
- The run then completes. At `DRIVE_STOP` the drive exits with `inflight` empty, and the pending retry is dropped without an error.
- 6.3n ("push: stage 0 is closed") looks like the same root, when the retry lands after the close.

Paths of the same kind to check:
- a `Replacement` retry;
- the worker wall's `GiveUp` under `ErrorPolicy::Skip`;
- the Parquet sink's `roll_all` and `finish`.

**The invariant (PM's decision):** check rows per queue and per stage, which holds for any job. Then check end to end, from the plan's rows through the source's pushed rows to the sink's rows. Apply the end-to-end check only when every stage reports that it kept its rows (rows_in = rows_out and nothing skipped). Each stage already counts `rows_in` and `rows_out`.
