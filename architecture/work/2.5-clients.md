# 2.5: The CLI and the clients

- **System design:** `architecture/moruna-os-system.md`, section 2E.
- **Needs:** 2.1 (merged). A booted node is not needed: tests run against `moruna-api-server` on the
  host once 2.2 is merged, and against a fake until then. **Rules:** `architecture/work/_rules.md`.

## Goal

Three ways to call a node: the `moruna` CLI, a Rust client, and a Python client, all generated from
or built on 2.1's single source.

## Build

1. **Rust client:** crate `crates/moruna-api-client` in the root workspace. Blocking, on the root
   workspace's `reqwest` with rustls. It depends on `kernel/api/types` by path and covers the three
   operations from its operations table. `Client::new(url, token, pin)`. With a pin, a rustls
   verifier that accepts a certificate exactly when its DER's SHA-256 matches. Without one, normal
   verification.
2. **The CLI:** `moruna node --url <https://…> --token <token> [--pin <hex>] [--audit]` in
   `crates/moruna-py/src/bin/moruna.rs`. It prints the node document, or the audit with `--audit`,
   as JSON on stdout. Errors go to stderr, with exit code 1.
3. **Python client:** `tools/api/gen_python.py` reads `kernel/api/openapi.json` and writes
   `python/moruna/api/_generated.py`: one dataclass per schema, and one function per operation.
   Hand-written beside it: `python/moruna/api/__init__.py`, a `Client(url, token, pin=None)` on
   `urllib` and `ssl`. With a pin, it connects without verification, then refuses unless the
   peer certificate's SHA-256 matches. Standard library only.
4. **Drift test:** regenerating `_generated.py` must give the committed file.

## Success

- Against `moruna-api-server` run on the host over TLS with a generated identity: the Rust client,
  the CLI and the Python client each read `node` with an `observe` token, read `audit` with an
  `admin` token, and are refused with the wrong pin.
- The drift test fails when `openapi.json` changes without regenerating.
- Root workspace and Python checks pass (`tools/quality` as the hook runs them), with 80% line
  coverage of what you add.

## Not yours

Issuing tokens (tests make their own), `jobs` operations, a booted node.

## Report

The commits, test results and coverage.
