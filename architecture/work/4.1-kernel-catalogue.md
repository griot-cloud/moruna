# 4.1 and 4.3: the kernel catalogue, and `filter` and `take`

- **System design:** `architecture/moruna-os-system.md`, sections 4A (the catalogue), 4B, 4C.
  **Rules:** `architecture/work/_rules.md`.
- **Why:** every other kernel item (4.2, 4.4, 4.5, 4.6) writes a specification and a conformance
  corpus in the formats this item defines. **Commit the formats first**, as their own commit, and
  tell the PM the hash: four agents are waiting to use them.

## Build

1. **The specification format,** `crates/moruna-kernels/spec/<name>.md`:
   - a fixed set of headings: identity (namespace, name, version); signature in Arrow types and
     parameters; nulls; overflow; rounding; ordering; empty input; state shape (4C); the most
     output an input can produce; the state it keeps; tolerance, for kernels that declare one;
   - a template, and a check in the runner that every spec has every heading.
2. **The conformance corpus format,** `crates/moruna-kernels/conformance/<name>/`:
   - cases of input batches, parameters and expected output, as Arrow IPC files;
   - a small JSON index naming each case, its kernel version and what it tests;
   - a declared tolerance where the spec has one.
3. **The runner:** a test in `moruna-kernels` that runs every corpus against every implementation
   the build has, keyed by (namespace, name, version). An implementation that fails one case of a
   version cannot claim that version. Today the only implementations are the CPU references.
4. **Versioned identities:** `moruna.<name>@<version>` in `moruna-kernels`. A kernel's fingerprint
   stays `sha256(name, canonical args, crate version)`; the identity is what a job and the plane
   name.
5. **`filter` and `take`** (item 4.3), as the first two kernels in the new form: spec, corpus and
   CPU reference under the existing `Kernel` trait.
   - `filter` gives the compacted batch or a UInt32 selection array; the platform chooses the
     form, so the kernel offers both.
   - `take`'s values may be fixed at configure.
   - The existing `moruna.std.filter(expr)` keeps working; its small expression language is
     replaced by `expr`'s in 4.2, not here.

## Success

- The runner runs both corpora against both references.
- Every case of a corpus states what it tests: nulls, empty, all-false, all-true, a sliced input,
  and dictionary and nested inputs for `take`.
- Enrich's filter (`bench/vm/workloads.py`) as `filter`, on a month, gives 0.6.6's rows.
- Coverage of added code at 80% or more.

## Report

The formats (with the commit that defines them), the runner, the two kernels, and coverage.
