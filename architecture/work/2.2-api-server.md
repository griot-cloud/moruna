# 2.2: The API server library

- **System design:** `architecture/moruna-os-system.md`, sections 2A and 2B.
- **Needs:** 2.1 (merged). **Rules:** `architecture/work/_rules.md`.

## Goal

`moruna-api-server`: the whole API server as a library, tested on the host. Item 1.3's
`moruna-node-api` program wires it into the node afterwards, so nothing here touches
`kernel/node`.

## Build

1. **The crate:** `kernel/api/server`, package `moruna-api-server`, in the kernel workspace,
   `#![no_std]` with `alloc`. It depends on `moruna-api` (2.1), `rustls` and `ring` at the
   versions the network server already uses, `httparse`, and `serde_json` without std. It builds
   for the host and for the kernel's user target.
2. **The transport trait:** a connection is a non-blocking byte stream with `read`, `write` and
   `close`. The server is a state machine driven by the caller: accept a connection, give it
   bytes, take bytes to send, ask it the time. No threads, no async runtime.
3. **TLS:** rustls `ServerConnection`, TLS 1.3 only. The server's identity is either the operator's
   certificate and key (node config's `tls`), or the node's own, made by `Identity::generate`
   exactly as 2B describes. `Identity::fingerprint` gives the console line's hex.
4. **HTTP/1.1:** request line and headers through `httparse`; `Content-Length` bodies only;
   keep-alive; `Connection: close` honoured. No HTTP/2, compression, cookies or cross-origin
   headers. 2B's limits exactly: 16 KiB of headers, 1 MiB of body, 64 open connections, 60 s idle.
   Over a limit: `invalid` (headers, body) or `busy` (connections), then close.
5. **Routing:** from 2.1's operations table only. `GET /v1/health`, `GET /v1/node`,
   `GET /v1/node/audit`. Anything else: `not_found`. A known path with another method: `invalid`.
   Every error is 2A's error body with its code's status.
6. **The node document** comes from a `NodeFacts` value the caller supplies; the server only
   serializes it. In this item, no token check: every operation answers. 2.3 adds tokens.

## Success

- Host tests through a real rustls client over an in-memory transport: a handshake, then each
  operation's answer, field for field as 2A.
- Each limit has a test that reaches it and gets the right answer and a close, never a panic.
- A fuzz-style test feeds 10,000 random byte streams to the HTTP layer, with a fixed seed: no panic.
- `Identity::generate` gives a certificate that rustls's own client accepts when pinned to its
  fingerprint, with 2B's subject, validity and extensions, checked by parsing the DER.
- Builds for the user target; clippy and fmt clean; 80% line coverage.
