# 6.3n: a run short of arena can end "push: stage 0 is closed"

- **System design:** `architecture/moruna-os-system.md`, section 3A (a read that does not fit is
  cut or waits; it is never lost). **Rules:** `architecture/work/_rules.md`, and 6.3's steps.
- **Found by:** 6.3j's host test (2026-11-18): 3 of 12 runs of a 160 MiB input ended
  `staging: push: stage 0 is closed`. None did when the stage had more arena.

## The lead, by reading only

`close_when_exhausted` (`crates/moruna-scheduler/src/source_drive.rs`, about line 1022) closes
the source's queue when no read is in flight and the cursor is past the plan. A read the arena
refused waits in `waits.retry` (about line 946), which that check does not look at. The retried
read then lands and is pushed into a closed queue, and the job fails.

It would hit any job that is short of arena when its source's last read lands. This is a
correctness defect: a job that should finish fails.

## Do

1. **Reproduce it deterministically** in a host test: a source whose last read is refused by the
   arena and retried after the cursor has passed the plan. The run must complete with every row.
   It fails today.
2. **Fix it where the queue is closed:** a source is exhausted only when nothing is in flight,
   nothing waits to be retried, and the cursor is past the plan. Check every other place that
   decides a source or a stage is done against the same rule, and list them.
3. **Run the scheduler, runtime and sinks suites,** and a loop of the reproducing test (at least
   200 runs) to show it no longer fails.

## Report

The test, the fix, the list of places checked, the loop's result, coverage and the commits.
