# 3.8: The proof

- **System design:** `architecture/moruna-os-system.md`, section 3 (all of it).
- **Needs:** 3.1, 3.3 or 3.5, 3.6, 1.6 and 1.13 merged. **Rules:** `architecture/work/_rules.md`.

## Goal

The four NYC taxi jobs run through the node's API on real cloud nodes, and give 0.6.6's output.

## Build

Nothing new in the OS. A script, `bench/node/proof.py`, that against one node's URL and token:
1. registers the jobs' functions (3.6), signed with a test function key in that node's config;
2. submits Score, Occupancy, Enrich and Audit (`bench/vm/workloads.py`) on one month, then on all
   of 2024 (41.2M rows), reading from and writing to the node's volumes (3.3) or Blob (3.5);
3. follows each job's events to its report (3.7);
4. checks each output's rows and canonical hash against 0.6.6's (`bench/vm/canon.py`, the
   references in `~/moruna-data/nyc/`).

## Success

All eight runs (four jobs, a month and the year) pass on:
- a Servercore node (1.6's flavor, ru-3);
- an Azure node (`Standard_D4s_v4`, zone 3, `griot-dev`).

Times are recorded but are not the point here; the benchmark is 6.2.

## Cloud

The PM creates and deletes the nodes, through `kernel/node/OPENSTACK.md` and `AZURE.md`. The agent
writes the script, tests it against a node under QEMU, and gives the PM the command.

## Report

The commits, the QEMU run, and the PM's two cloud runs' output.
