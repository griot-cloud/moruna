# 6.1: The benchmark harness in griot-dev

- **System design:** `architecture/moruna-os-system.md`, section 6.
- **Needs:** 1.13 and 3.5 merged for a real run. The harness and its dry run need nothing.
  **Rules:** `architecture/work/_rules.md`; creates resources in `griot-dev` only.

## Build

`bench/node/`: one command on the Mac, `bench/node/run.py --plan <plan>`, which:
1. creates the resource group, the Blob container with the data, the Moruna node (the VHD, through
   `AZURE.md`'s steps), and one Linux machine for the other engines, each on `Standard_D4s_v4` in
   zone 3;
2. runs each job on each engine as 6B says, through the API for Moruna and over `az vm run-command`
   for Linux;
3. collects the results into `bench/node/results/<date>/` and the table into
   `architecture/benchmark-log.md`;
4. deletes the resource group, always, even on failure.

Reuse `bench/vm/` (the plans, `canon.py`, the report) where it fits.

## Success

A dry run (`--dry-run`) creates the resource group with nothing in it, prints every step, and
deletes it.

## Report

The commits and the dry run's output.
