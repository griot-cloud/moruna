# 1.8: The core on Hyper-V

- **System design:** `architecture/moruna-os-system.md`, sections 1B and 1F ("The core on Hyper-V").
- **Findings to read:** `architecture/work/1.7-azure-findings.md`, sections 1 and 2.
- **Needs:** 1.2 (it patches the same OSTD files). **Rules:** `architecture/work/_rules.md`.

## Goal

Moruna's core boots on a Hyper-V Generation 2 machine as far as `services started`: it finds the
hypervisor, takes its clock rates from it, and boots without a PCI bus.

## Build

1. **Finding Hyper-V:** CPUID.1:ECX[31], then leaf `0x40000001` answering `Hv#1`. One line on the
   console: `moruna: hypervisor hyperv`. On KVM it prints `moruna: hypervisor kvm`; on none, nothing.
2. **Clock rates,** in the vendored OSTD, as marked patches:
   - the TSC rate tries kvmclock, CPUID leaf `0x15`, then Hyper-V's MSR `0x40000022` when leaf
     `0x40000003` says the frequency MSRs are readable, and the PIT last (with 1.2's deadline);
   - the APIC timer takes its rate from MSR `0x40000023` on Hyper-V, and is calibrated as today
     elsewhere.

   Use the vendored `hvdef` for every constant.
3. **No MCFG:** `root.ecam` covers an empty range when the firmware describes no PCI configuration
   space. `devices` then finds no PCI function, prints `devices: no PCI bus on this machine`, and
   serves. If an empty range can't be expressed, ask.
4. **The hypercall page and the guest OS ID,** set up at boot when Hyper-V is found, for item 1.9c
   to use:
   - the guest OS ID in the TLFS's open-source form. Propose the exact value with its TLFS
     citation in your report; use OS type "undefined" if none fits;
   - the page mapped executable in kernel mode only. No call is made in this item.
5. **Old PC devices:** from the findings' section 1, every device OSTD or the core touches that a
   Generation 2 machine lacks gets a presence check before use.

## Phase 1: no Hyper-V needed

- Host tests of the choice of clock source over recorded CPUID and MSR answers: KVM, Hyper-V with
  and without the frequency MSRs, bare metal with leaf `0x15`, nothing at all.
- **A booted check without MCFG:** the cloud image on QEMU's `-machine pc`, which has none,
  reaches `services started` with the `no PCI bus` line. Add the machine as an optional argument
  of `uefi-boot.sh`; q35 stays the default.
- CI's boot still passes on 1 CPU under the emulator rule.

## Phase 2: on Azure, when the PM says

The image booted on Azure reaches `services started` on the serial console (item 1.7b's setup).

## Not yours

VMBus, the calls on `root.hyperv` (1.9c), storvsc, netvsc, the Azure `platform`.
