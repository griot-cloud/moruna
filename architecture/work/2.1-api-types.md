# 2.1: The API's types

- **System design:** `architecture/moruna-os-system.md`, sections 2A and 2C (the claims only).
- **Needs:** nothing. It builds and tests on the host.

## Goal

One crate, `moruna-api`, that holds step 2's requests, responses, errors and token claims as Rust
types, and generates the OpenAPI document and the MCP tool list from them.

## Build

1. **The crate:** `kernel/api/types`, package `moruna-api`, in the kernel workspace. `#![no_std]`
   with `alloc`, because the node's `api` process uses it; `serde` with derive. A `schema`
   feature, for the host only, adds what generation needs.
2. **The types,** with these exact JSON names and no others:

   | Type | Fields |
   |---|---|
   | `Health` | `status`: `"ok"` |
   | `Node` | `version` string, `instance` string, `cloud`, `cores` u32, `memory_bytes` u64, `executors` list, `boot_ms` u64, `time` u64 (Unix seconds), `health`: `"ok"` or `"degraded"` |
   | `Executor` | `kind`: `"cpu"`; `slots` u32 |
   | `Cloud` | `"openstack"`, `"azure"`, `"none"` |
   | `Audit` | `records`: list of `AuditRecord`, newest first |
   | `AuditRecord` | `time` u64, `key` string, `scope` list of `Scope`, `operation` string, `status` u16 |
   | `Scope` | `"observe"`, `"submit"`, `"admin"` |
   | `ErrorBody` | `error`: `{ "code", "message" }` |
   | `ErrorCode` | `invalid` 400, `unauthorized` 401, `forbidden` 403, `not_found` 404, `conflict` 409, `busy` 503, `internal` 500 |
   | `Claims` | `aud` string, `exp` u64, `scope` list of `Scope` |

   - `AuditRecord.key` is the first 16 hex characters of the SHA-256 of the token key's public
     bytes, or empty when the call carried no valid token. This crate only carries the string.
   - `Claims` refuses unknown fields. `Scope` has `covers`: `admin` covers `submit`, and `submit`
     covers `observe`.
3. **The operations table,** one constant list that the generators and, later, the server read:

   | ID | Method and path | Scope | Response |
   |---|---|---|---|
   | `health` | `GET /v1/health` | none | `Health` |
   | `node` | `GET /v1/node` | observe | `Node` |
   | `node_audit` | `GET /v1/node/audit` | admin | `Audit` |

4. **Generated files,** checked in:
   - `kernel/api/openapi.json`: OpenAPI 3.1, bearer-token security on every operation but
     `health`, the error body on every operation.
   - `kernel/api/mcp-tools.json`: one tool per operation, named `moruna_<id>`, with its input and
     output schemas.

   One command regenerates both. Its output is byte for byte stable.
5. **New dependencies** pass `cargo deny` as the workspace runs it. If one does not, ask.

## Success

- Each type round-trips the JSON written in section 2A, field for field.
- `Claims` with an unknown field is refused. `ErrorCode` maps to its status. `covers` is right
  for all nine pairs.
- A drift test fails when a type or the table changes and the two files are not regenerated.
- The crate builds for the host and for the kernel's user target.
- Line coverage of the crate is at least 80%.
