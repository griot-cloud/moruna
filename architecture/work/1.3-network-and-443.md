# 1.3: DHCP, and `api` on port 443

- **System design:** `architecture/moruna-os-system.md`, section 1C.
- **Needs:** 1.1; 1.2 for the fatal path. **Rules:** `architecture/work/_rules.md`.

## Goal

The node takes its address by DHCP, and exactly one port answers: 443, owned by a new `api`
process, which in this step accepts a connection and closes it.

## Build

1. **`api` as a process.** New crate `kernel/node/api`, package `moruna-node-api`, a program on
   `moruna-svc` like the other services. In this step it opens its listener on 443, accepts each
   connection and closes it at once. Its account is 64 MiB.
2. **The profile.** `kernel/node/cloud.image` gains `program:api image.api`. Exactly these
   additions to `node.conf`:

   ```
   service api image.api 67108864
   link network listen-api api network
   ```

   And `network.conf` becomes exactly:

   ```
   moruna-netstack 1
   interface wan card=net0 dhcp
   grant listen-api rights=listen local=0.0.0.0/0@443 sockets=64
   ```

   If the parser refuses a line as written, ask; do not reword it.
3. **The network line.** On the first DHCP lease, the network server prints exactly
   `moruna: network wan <address>/<prefix> gateway <address>`.
4. **The network deadline.** No lease within 30 s of the network server's start: it prints
   `moruna: fatal network: no DHCP lease within 30 s` and exits with failure (1.2's path).

## Success

- Booted with `uefi-boot.sh`, with `hostfwd=tcp::8443-:443` and `hostfwd=tcp::8444-:444` added to
  its user network:
  - the network line shows QEMU's lease (10.0.2.15/24 gateway 10.0.2.2);
  - a TCP connection to the host's 8443 is accepted and then closed by the node;
  - a connection to 8444 is refused.
- With no network card in the machine: the network fatal line within 35 s, then a power-off.
- A host test of the network server's policy: a grant with `rights=listen` only refuses an outbound
  connect. If that test exists already, cite it.
- 1 and 2 CPUs.

## Not yours

TLS, HTTP, `platform`, any outbound grant, IPv6.

## Report

The commits, the boot logs, and the connection checks' output.
