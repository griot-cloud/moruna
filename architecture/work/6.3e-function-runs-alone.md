# 6.3e: a function runs as one process however many CPUs the job has

- **System design:** `architecture/moruna-os-system.md`, section 3E (amended 2026-11-18: a
  function runs one instance per CPU of the job unless it declares fewer), 3A, and 5A–5C (the SDKs).
  **Rules:** `architecture/work/_rules.md`, and 6.3's steps.
- **Found by:** 6.2 run 3 (`bench-run3/bench/node/results/202611181311/node/score-moruna-node-r*.job.json`).
  The PM's analysis follows.

## The miss

Score, year, Azure Blob, a D4s_v4 node with a budget of 4 CPUs: the node takes 93.2 s, against
33.9 s for 0.6.6's Rust function on Linux.
- The report says `gate-score: 1 tasks, busy_peak 1, 540 batches, cpu 1`. The workers spent 82.6 s
  of the 93.5 s waiting for the one task's answers, with a busy fraction of 0.23.
- The engine's bottleneck timeline is Memory for 88 s: batches waiting for the function.
- Occupancy and Audit read the same 803 MB in 19–20 s, so reading is not the limit.

**Where:**
- `crates/moruna-micro/src/task.rs` `ImageTask::kind()` makes every image task
  `Stateful { max_instances = memory.len() }`.
- `memory.len()` is `layout::processes(env)`: the image's `MORUNA_PROCESSES`, or 1.
- The gate tasks the benchmark registers (`~/moruna-data/gate-tasks-1fceede8`) declare nothing, so
  they get 1. On the Linux gate (`bench/vm/gate_plan.py`) a value was packaged per machine.

## Do

1. **Write the defect as a test:** a function that declares nothing, in a job with 4 CPUs, runs 4
   instances and its batches go to all of them (busy_peak 4). It fails today.
2. **Build 3E's amended rule:**
   - instances = the job's CPUs (`budget.cpu`, or the node's CPUs), capped by `PROCESSES_MAX` and by
     the image's `MORUNA_PROCESSES` when it declares one;
   - each instance funded from the run's accounting as `native_children` does today.

   Say what happens when the memory share per instance falls below a function's least, and ask the
   PM if it needs a choice.
3. **Find every function that keeps state across batches** and make it declare its count, or show
   that it merges correctly across instances. Cover the C SDK's `c-sum` (a running total), the gate's
   seven functions, the Python shim's stateful classes, and the SDK examples. Give the list with each
   one's verdict.
4. **The SDKs say how to declare it** (5A Rust, 5B C, 5C Python), in their guides.
5. **Booted check:** the boot image's function tests pass (FN lines), and a 4-CPU boot shows a
   map function at busy_peak 4.
6. **The host table:** the year Score into a count, at 4 CPUs, before and after (wall, busy_peak,
   the function's waiting time).

## Refused

Setting `MORUNA_PROCESSES` in the benchmark's task images; any count tuned to the benchmark machine.

## Report

The test, the rule as built, the list of stateful functions with their declarations, the booted
lines, the table, coverage and the commits.
