# 3.8b and 2.6: the proof on Servercore, and the API's proof on both clouds

- **System design:** `architecture/moruna-os-system.md`, sections 1E, 2 (2.6) and 3 (3.8).
- **Needs:** 1.6 (done: Servercore run 10, 2026-11-18, image 5b6bfbf9, `ready` with boot_ms 1982),
  3.8's Azure half (done), and 3.8's tooling: `kernel/node/tools/azure-up.sh --proof` and
  `bench/node/proof.py`. **Rules:** `architecture/work/_rules.md`. Agents create nothing in any
  cloud: the PM runs every cloud step.

## Goal

1. **3.8 on Servercore:** the four NYC taxi jobs, on a month and on the year, through the node's
   API, give 0.6.6's rows and canonical hashes. All eight runs pass, as on Azure.
2. **2.6 on both clouds:** from outside the cloud, the node answers over HTTPS and over MCP; a bad
   token is refused.

## Build

1. **`openstack-up.sh --proof`,** as `azure-up.sh --proof` does it:
   - the flavor `SL1.4-16384-128` (4 vCPU, 16 GiB, like Azure's D4s_v4), region ru-3;
   - the node config with the test function key;
   - when ready, `bench/node/proof.py` against the node's floating IP, keeping results in `RUN/proof`;
   - then the 2.6 checks, then delete everything as the script does today.

   Keep its bounded calls, its reverse delete and its leftover check.
2. **The data, from Azure Blob, over the internet** (az:// with a SAS, as 3.5 reads it). A Servercore
   node reads it through `moruna-net`.
   - Add `kernel/node/tools/nyc-blob.sh`. In `griot-dev` it creates a storage account and a
     container. It fills them in Azure, with no upload from the Mac (about 0.3 MB/s): one small Linux
     VM runs 6.2b's `bench/node/engines/data-linux.sh` and `dataprep.py`, which fetch, normalize and
     hash-check the twelve months against `plans/nyc-2024.json`. Then it deletes the VM. It prints
     the account, the container and a read-only SAS valid for a few hours, in a mode-600 file, and
     deletes everything on `--delete`.
   - The SAS reaches proof.py only through its environment, as on Azure. It is never shown (3E).
3. **2.6's checks,** one Python script used by both `azure-up.sh` and `openstack-up.sh`:
   - `GET /v1/health`, and `/v1/node` with a valid token;
   - over MCP, list the tools and call `moruna_node`;
   - a token signed by another key, and one with a wrong `aud`, each refused with 401.

   The rest of 2.6, killing `api` and seeing the node still answer, cannot be done on a cloud node:
   a node has no way in but the API. 2.2c's booted test covers it, and the report says so.
4. **Tests:** `test_openstack_up.py` covers `--proof` in a dry run; the 2.6 script runs against a
   node under QEMU (`node-up.sh`); `nyc-blob.sh` has a dry run.

## Success

The PM's runs: all eight 3.8 runs pass on Servercore, and the 2.6 checks pass on Servercore and on
Azure.

The commits, the dry runs, the QEMU run of the 2.6 checks, and the exact commands for the PM.
