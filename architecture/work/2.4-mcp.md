# 2.4: MCP on the same port

- **System design:** `architecture/moruna-os-system.md`, section 2D.
- **Needs:** 2.3. **Rules:** `architecture/work/_rules.md`.

## Goal

An MCP client connects to `POST /mcp` with the same token and calls the node's tools.

## Build

1. **Transport:** MCP's Streamable HTTP, stateless. `POST /mcp` carries one JSON-RPC 2.0 message
   and is answered with one JSON response (`Content-Type: application/json`). No server-sent
   stream, no session ID. A notification is answered `202` with no body. `GET /mcp`: `405`.
2. **Methods:**
   - `initialize`: answers protocol version `2025-06-18`, server info `{"name":"moruna","version":
     <node version>}`, and capabilities `{"tools":{}}`;
   - `notifications/initialized`: `202`;
   - `tools/list`: the tools from `kernel/api/mcp-tools.json` (2.1), exactly;
   - `tools/call`: runs the operation of the tool named, with the same scope rule as HTTP. The
     result is `structuredContent` holding the operation's JSON, with the same JSON as one text
     content item. An operation's error is a tool result with `isError: true` and 2A's error body.
   - `ping`: an empty result.

   Anything else: JSON-RPC error `-32601`. Malformed JSON: `-32700`.
3. **Tokens:** every MCP request needs a token, `observe` at least (2C). A tool call needs its
   operation's scope.
4. **Audit:** each `tools/call` is one audit record, with the operation's ID.

## Success

- Host tests over TLS: initialize, list, and call each of the three tools; a call without the scope
  is refused as a tool error; an unknown method gets `-32601`.
- The tool list served equals `mcp-tools.json` byte for byte after parsing.
- 80% line coverage of what you add.

## Not yours

Booting (1.3 and 1.4 wire the server into the node; 2.6 proves it on the clouds), SSE streams
(step 3), resources and prompts.
