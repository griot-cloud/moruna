# 3.6b: A function address's query is never shown

- **System design:** `architecture/moruna-os-system.md`, section 3E ("An address's query is a
  credential").
- **Needs:** 3.6 (merged). **Rules:** `architecture/work/_rules.md`.

## Why

3.8's cloud tooling registers functions at SAS addresses. The node shows those addresses whole in two
places:
- `GET /v1/functions` (observe scope);
- a failed fetch's diagnostic (`kernel/node/functions/src/https.rs`), which reaches the job's events.

So the SAS reaches anyone with an observe token, and it reaches the logs.

## Build

1. One function that shows an address: scheme, host and path, with any query replaced by `?…`. Use it
   for every place the node shows an address: `GET /v1/functions`, events, diagnostics, console and
   log lines. The address is kept whole only where admission fetches.
2. Tests:
   - a registered SAS address listed by `GET /v1/functions` shows `?…`;
   - a fetch that fails on a SAS address gives a diagnostic without the query;
   - an address with no query is shown as it is.
3. Grep the node for other places an address is formatted, and route them through the same function.

## Report

The commits, the tests, and the places changed.
