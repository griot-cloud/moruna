# 3.2c: A job with no budget gets the node's job bound, pinned by a test

- **System design:** `architecture/moruna-os-system.md`, section 3A (the budget).
- **Needs:** 3.2 (merged). **Rules:** `architecture/work/_rules.md`.

## Why

3A says a document with no `budget.memory_bytes` gets the node's job bound (`job_memory_bytes`). 1.3c
observed that this already holds: on a 2 GiB node, with no budget and with budget =
`job_memory_bytes`, the engine starts with the same 326 MiB arena and 108 MiB scratch, which is 3A's
split of the 590,229,504-byte bound. No test pins it.

## Build

1. A host test: a document with no budget, validated and submitted, runs with the node's job bound,
   and the report says the budget used.
2. A document with an explicit budget keeps it, and one larger than the bound is refused as today.
3. Change code only if a test shows the rule does not hold. Then fill the budget in where node mode
   fills a document's gaps, before the check.

## Report

The commits and the tests, and whether any code had to change.
