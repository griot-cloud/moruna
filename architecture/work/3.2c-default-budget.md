# 3.2c: A job with no budget gets the node's job bound

- **System design:** `architecture/moruna-os-system.md`, section 3A (the budget).
- **Needs:** 3.2 (merged). **Rules:** `architecture/work/_rules.md`.

## Why

A job document that names no `budget.memory_bytes` runs on a node at the engine's host default:
326 MiB plus 108 MiB scratch on a 2 GiB node, whose job bound is far larger. 1.3c's copies ran out of
memory that way. A node runs one job, so 3A now says an unbudgeted job gets `job_memory_bytes`.

## Build

1. Where node mode fills in a document's gaps before the check (`api` or `node-admission`, whichever
   holds `job_memory_bytes`; the engine's check must see the filled document), set
   `budget.memory_bytes` to the node's job bound when the document names none.
2. `validate`'s answer and the job's report show the budget used.
3. A document's own budget is unchanged: a larger one than the bound is refused as today.

## Success

- A host test: a document with no budget, validated and submitted, runs with
  `budget.memory_bytes == job_memory_bytes`, and the report says so.
- A document with an explicit budget keeps it.
