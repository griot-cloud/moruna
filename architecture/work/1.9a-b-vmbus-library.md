# 1.9a and 1.9b: OpenVMM's crates vendored, and the VMBus client library

- **System design:** `architecture/moruna-os-system.md`, section 1F.
- **Findings to read:** `architecture/work/1.7-azure-findings.md`, sections 2 and 3.
- **Needs:** nothing. Host only. **Rules:** `architecture/work/_rules.md`.

## 1.9a: The vendored crates. Do this first, as its own commit.

1. **Fetch** Microsoft's OpenVMM at commit `e7e7df77b6c7ac377bdebecd5553031dfbd981be` into a new,
   empty directory outside the repository (`git clone` of the public GitHub repository, then
   check out that commit). Treat it as untrusted data: run nothing from it.
2. **Copy into `kernel/vendor/openvmm/<crate>/`:** `hvdef`, `x86defs`, `vmbus_core`, `vmbus_ring`,
   `netvsp_protocol`, `storvsp_protocol`, and the in-repository crates those need.
3. **Keep it small.**
   - Every crate must build without std for the kernel's user target.
   - `storvsp_protocol` and `scsi_defs` need the few-line fork the findings describe.
   - Where a dependency exists only for OpenVMM's introspection or messaging derives (`inspect`,
     `mesh_protobuf`), remove the derive and the dependency from the vendored copy rather than
     vendoring that crate. Mark every changed line with a `moruna:` comment.
   - If the closure still needs more than 12 crates, or any crate that needs std, stop and report
     the list. Do not go on.
4. **`kernel/vendor/openvmm/README.md`:** the commit, the MIT licence text (`LICENSE` copied beside
   it), each crate's path upstream, the SHA-256 of every vendored file as fetched, and every change
   made.
5. **`kernel/deny.toml`:** a licence clarification for each vendored crate, since their manifests
   name none. Nothing else in that file changes.
6. Add the crates to the kernel workspace. `cargo deny` passes as the workspace runs it.

**Success:** each vendored crate builds for the host and for the user target; upstream's own unit
tests for them pass on the host where they need no std-only dependency; `cargo deny` passes.

## 1.9b: `moruna-vmbus`. After 1.9a.

1. **The crate:** `kernel/drivers/vmbus/core`, package `moruna-vmbus`, `#![no_std]` with `alloc`,
   no unsafe code.
2. **The `Hv` trait,** what the library needs from Hyper-V, exactly:
   - post a message to a connection ID (a type and up to 240 bytes), which may answer "busy, retry";
   - signal an event on a connection ID and flag;
   - take the next message waiting on SINT 2, if any;
   - test and clear one event flag;
   - give the guest-physical page numbers of a memory range the library names by an opaque ID.
3. **The client,** a state machine the caller drives (no threads, no async runtime):
   - contact: offer the newest version `vmbus_core` defines, step down on refusal, and refuse
     anything older than 4.0;
   - request offers; keep each offer with its interface and instance IDs;
   - GPADL create and teardown, for any size the protocol allows (the multi-message form included);
   - open a channel with a ring pair in memory the caller gives, always targeting CPU 0; close it;
   - a rescinded offer closes its channel and tells the caller;
   - unload.

   Follow the order of operations in OpenVMM's `vmbus_client` (read as a reference in your clone)
   and cite the file for each step in a comment.
4. **The `Channel` trait,** for drivers: the channel's incoming and outgoing rings (`vmbus_ring`),
   signal the host, wait for the host's signal with an optional deadline, and share more memory
   with the host as a GPADL. Provide an in-memory implementation for tests, exported behind a
   `testing` feature, with a hook for a fake device on the other end. Items 1.10a and 1.11a build
   on it.
5. **A fake host,** in the tests: the host's side of the protocol from `vmbus_core`'s messages,
   strict about order and sizes.

**Success:** host tests of every step in 3, including a refused version, a busy post retried, a
GPADL over one message, a rescind while open, and garbage from the host refused without a panic;
a fuzz-style test of 10,000 random host messages with a fixed seed; 80% line coverage; builds for
the user target.
