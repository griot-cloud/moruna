# 1.3b: The network server, hardened for a public port

- **System design:** `architecture/moruna-os-system.md`, sections 1C and 2B.
- **Needs:** 1.3 merged. Host first. **Rules:** `architecture/work/_rules.md`.

## Goal

The node's network server is the first code anyone on the internet reaches. Nothing they send may
crash it or exhaust its memory.

## Build

1. **The smoltcp panic.** `kn_t6_the_suite_passes_over_loopback` fails on the base: "attempt to
   subtract sequence numbers with underflow", smoltcp 0.12.0 `socket/tcp.rs:698`, from `Stack::poll`.
   - Find whether upstream fixed it (smoltcp's releases and issues). If a fixed release exists,
     move to it; if not, fix it in a vendored copy with a `moruna:` marker, and report it upstream
     in the item's notes (not sent: the PM sends it).
   - In release builds overflow checks are off, so the wrap is silent and the TCP state is wrong:
     treat it as a correctness bug either way.
2. **Socket memory is bounded per grant, lingering sockets included.**
   - A grant's `sockets=N` counts every socket of its listeners and connections until the socket
     is freed, closing and waiting states included.
   - A grant may set buffer sizes, `rx=` and `tx=` in bytes. The default stays as today.
   - The cloud profile's `listen-api` grant becomes
     `grant listen-api rights=listen local=0.0.0.0/0@443 sockets=81 rx=65536 tx=65536`: 80
     connections, as 2B's cap, plus the listener.
   - A socket refused for the cap is refused at accept, and the peer gets a reset.
3. **`kernel/net/stack/tests/suites.rs:19`**'s clippy failure, fixed.

## Success

- `kn_t6` passes; a test that reproduces the underflow fails before the fix.
- A host test: 10,000 connections opened and abandoned against a `sockets=81` grant never hold more
  than 81 sockets or more than 81 × (rx + tx) of buffers, and a valid connection afterwards
  is served.
- `cargo clippy` clean for `kernel/net`.

The commits, the upstream finding, and the test results.
