# 6.3h: a function's bytes out look inflated when its answer is kept in place

- **System design:** `architecture/moruna-os-system.md`, section 3A (a function's memory is
  measured; the controller sizes from what runs observe). **Rules:** `architecture/work/_rules.md`,
  and 6.3's steps.
- **Found by:** 6.3g's map (2026-11-18), in 6.2 run 3's node reports
  (`bench-run3/bench/node/results/202611181311/node/*.job.json`).

## The lead

- **Score:** out/in is 0.22 in three runs and 0.73 in three others, on the same data.
- **Enrich:** out/in is 14.8 to 18.7, where the function's real output is 1.17 times its input.
- **The effect:** the controller then believes Enrich amplifies 15 times, and sizes from that.

**Suspected:** an answer kept in place is counted once per column buffer
(`crates/moruna-micro/src/task.rs`, around lines 1512 and 1579).

## Do

1. **Confirm it** in the code and the reports: what `bytes_out` counts for an answer written in
   place, for one copied, and for one of several record batches.
2. **Write the defect as a test:** a function whose output is 1.17 times its input reports that,
   in place or not, on every run.
3. **Fix the count** where it is made. Then say what else read the wrong figure (the controller's
   amplification, the report, learning) and whether anything was sized from it.
4. **Show the reports' out/in** for the four gate functions before and after, on the host or in a
   booted check.

## Report

The cause, the test, the fix, what read the wrong figure, coverage and the commits.
