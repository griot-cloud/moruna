# 1.7b: Azure findings, the booted half

- **System design:** `architecture/moruna-os-system.md`, section 1F.
- **Needs:** 1.1 and 1.5 merged, and the PM's go-ahead in your brief. **Rules:**
  `architecture/work/_rules.md`, except that this item creates resources in Azure subscription
  `griot-stg`.

## Goal

See exactly where today's node image stops on Azure, so 1.8's work is aimed right.

## Build

1. A new resource group `moruna-boot-<yyyymmdd>` in `centralindia`. Never touch another group.
2. Upload 1.5's fixed VHD as a page blob, make a Generation 2 image from it, and create one
   `Standard_D4ls_v5` machine with security type `Standard`, boot diagnostics on, and no public
   inbound port.
3. Read the serial console log (`az vm boot-diagnostics get-boot-log`) after 5 minutes.
4. Delete the resource group, and show it is gone.

## Success

- The serial log, and a note in `architecture/work/1.7-azure-findings.md`, section 6: the last line
  printed, the stage it belongs to, and which of 1.7a's predictions it confirms or refutes.
- The resource group deleted.

## Limits

At most one hour of machine time. If the upload or the image is refused, stop and report.

## Report

The commands run, the log, and the note.
